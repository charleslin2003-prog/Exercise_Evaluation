### 這張表最重要的一句話

**兩支是獨立網頁應用程式，必須部署；一支是容器繫結腳本，絕對不能部署。**

為什麼有這個差別，不是風格問題，是 Google 的機制決定的：

- **網頁應用程式**（Config／ConfigWithSubmit）的客戶是**評核官的手機瀏覽器**。手機要能
  `fetch()` 一個網址拿到資料，而 Google 只在你按下「部署為網頁應用程式」時才會給你那個
  `/exec` 網址。沒有部署就沒有網址，手機只會看到載入失敗。
  又因為它們同時要讀「設定表」「紀錄表」「註冊表」三個不同檔案，而且多醫院模式下連要讀
  哪一個檔案都是執行時從註冊表查出來的，所以不可能把它們「掛在某一張試算表上」——沒有
  哪一張算得上是「那一張」。
- **容器繫結腳本**（Report.gs）的客戶是**坐在試算表前面的業主**。它的入口是 `onOpen`，這是
  一個「簡單觸發器」，Google **只會對掛在該試算表上的腳本**觸發它；它全程靠
  `SpreadsheetApp.getUi()`（跳對話框）和 `SpreadsheetApp.getActive()`（讀目前這張表）工作，
  這兩個在獨立專案裡根本沒有「目前這張表」可以指，會直接出錯。
  它既不需要被手機呼叫，也不需要網址，所以**不需要部署**：貼上程式碼、存檔、重新整理
  試算表，選單就出現了。這正是「報告方案 B」當初的設計目的——**讓業主永遠不必打開那個
  已經害過我們一次的部署對話框**。

> **已經踩過的坑**：`Report.gs` 和 `ReportDialog.html` 曾被誤貼進 `ConfigWithSubmit` 這個
> 獨立專案裡。那裡沒有壞掉任何東西（函式和變數名稱零衝突，端點重新實測仍正常），但它們
> 在那裡是**死的**：`onOpen` 不會被觸發，選單永遠不會出現，而且完全沒有任何錯誤訊息。
> 處理方式見 5 節第 2 列。

## 2. 架設順序與相依

一定要照這個順序。每一箱都只依賴它上面的箱子。

```
① 三張 Google 試算表（設定／紀錄／註冊表）
        ↓  ConfigWithSubmit 只認 ID，試算表不存在就無從談起
② ConfigWithSubmit 專案 → 部署 → 得到 RECORD_URL
        ↓                        ↓                       ↓
③ Start.dc.html 第 210 行    ④ Analysis.html        ⑤ Report.gs 的
   RECORD_URL                   第 163 行 RECORD_URL     REPORT_API_URL
        ↓                        第 166 行 ANALYSIS_KEY
⑥（可選）Config.gs 專案 → 部署 → Start.dc.html 第 202 行 CONFIG_URL
        ↓
⑦ 報告範本 Google 文件（六個必要錨點）
        ↓
⑧ Report.gs 容器繫結專案（不部署）→ 第一次產生報告
```

為什麼是這個順序：

| 先要有什麼 | 才能做什麼 | 原因 |
|---|---|---|
| 三張試算表 | ConfigWithSubmit | 程式裡第 21／24／95 行填的是試算表 **ID**，檔案不存在就只會拿到「你沒有存取所要求文件的權限」 |
| 紀錄表有正確的分頁名與標頭列 | 第一次送出分數 | `doGet`（載入題目）**完全不碰紀錄表**，所以紀錄表的問題要到第一個人按「送出」才會爆——演習進行中才發現就太晚了 |
| 設定表 `對應指標` 分頁五個欄標頭齊備 | 儀表板 `Analysis.html`、報告 | `doGet`（載入題目）也不碰 `對應指標`，所以欄名錯了要到**演習結束後要看報表**時才會爆（見 3.0 第 5 點） |
| **ConfigWithSubmit 已部署** | `Report.gs` | 報告產生器的 `REPORT_API_URL` 就是 `RECORD_URL`。這個網址在部署之前**不存在**，所以報告功能不可能先架 |
| ConfigWithSubmit 已部署且實測可用 | Config.gs（如果要留） | 反過來做會害到自己：一個正常的 Config 專案會讓表單「看起來一切正常」（題目、代號都載入得出來），把 ConfigWithSubmit 的毛病完全遮住，直到第一個人按送出 |
| 註冊表那一列已填好且實測 `?t=` 會路由 | 對外發出任何帶 `?t=` 的連結 | 註冊表那列如果指到別的紀錄表，兩種連結形狀會各寫到不同檔案，而且沒有任何機制能在當下察覺 |
| 報告範本 Doc 已建立 | 第一次產生報告 | `REPORT_TEMPLATE_DOC_ID` 沒有預設值，三個必填屬性缺一就直接拒絕 |
| 至少一筆評核官送出紀錄 | 產生報告 | 三組列數全空、或評核官 0 人時會直接中止（沙箱已有 101 列／5 位評核官，條件已滿足） |

快照，從 HEAD 刪檔案不可能改到 `RECORD_URL` 的行為；打開那個部署對話框才是唯一會弄壞它的
動作。

#### 步驟 1–6：先做報告範本 Google 文件

1. 用**跟試算表同一個帳號**登入 drive.google.com → 新增 → **Google 文件**
   （必須是原生 Google 文件；上傳的 `.docx` 或 PDF 會被直接拒絕，錯誤訊息是
   「指到的不是 Google 文件」）→ 命名為 `演習評核報告範本`。
   範本只會被**讀取和複製**，永遠不會被程式改動，所以可以一直重複使用。
2. **六個必要錨點**，缺任一就硬性拒絕產生。**一個錨點自己占一行**（按 Enter 分行，
   不要把兩個打在同一行）：
   `{{SEC_摘要}}`　`{{SEC_基本資料}}`　`{{SEC_評核方法}}`　`{{SEC_資料品質}}`
   `{{SEC_總體結果}}`　`{{SEC_附錄C}}`
3. **選填錨點**（想要哪一章就放哪一個；章節順序＝錨點在文件裡的先後順序）：
   `{{SEC_目錄}}`　`{{SEC_4S}}`　`{{SEC_潛能}}`　`{{SEC_覆蓋率}}`　`{{SEC_情境}}`
   `{{SEC_學習}}`　`{{SEC_排序}}`　`{{SEC_觀察紀錄}}`　`{{SEC_評核官差異}}`
   `{{SEC_前次比較}}`　`{{SEC_改善行動}}`　`{{SEC_結論}}`　`{{SEC_附錄A}}`
   `{{SEC_附錄B}}`　`{{SEC_附錄D}}`
   **刪掉某個選填錨點，就是不產生那一章。永遠不要改程式裡的 `SECTIONS_`。**
4. **錨點規則**（檢查設定會逐條檢查，而且不合格就直接拒絕產生）：
   - 那一段**只能有錨點本身**，前後不能有任何其他文字，連一個空白都不要。
   - 必須是**本文最上層段落**：不能是項目符號／編號清單的一項，也不能在表格格子裡。
   - 不能放在頁首／頁尾。
   - 樣式用「一般文字」：選那一行 → **格式 → 段落樣式 → 一般文字 → 套用「一般文字」**。
   - **用鍵盤直接打進去**，不要從網頁或這份文件複製貼上——貼上常常把樣式、清單格式或多餘
     的換行一起帶進去，而那正是上面三條最常被破壞的原因。
   - 打完請自己唸一遍大括號是**兩個**（`{{` 和 `}}`）、`SEC_` 後面沒有空格。
5. 封面頁打上要被填入的 token（打了就會替換，沒打不會報錯，只在檢查時列為警告）：
   `{{機構名稱}}`　`{{演習名稱}}`　`{{演習主題}}`　`{{演習類別}}`　`{{演習日期}}`
   `{{機構代號}}`　`{{演習代號}}`　`{{評核官人數}}`　`{{資料列數}}`　`{{報告產生時間}}`
   `{{報告編號}}`　`{{匿名模式}}`
   **不要加 `{{報告版次}}`**，除非你打算在每份複本裡自己手填——它刻意不在替換名單裡，
   會原字印出來，並且每次都觸發「還有未替換的 `{{`」警告。
6. 複製範本的檔案 ID（網址 `/d/` 和 `/edit` 中間那一長串）。

#### 權限

- 演習評核_設定：**編輯者或擁有者**（要插入 `報告快照` 與隱藏的 `_報告暫存` 分頁）。
- 範本 Doc：至少檢視，實務上建議**編輯者或擁有者**（唯讀檔案 `DocumentApp.openById`
  可能失敗，錯誤訊息會明講）。範本只會被讀取和複製，永不被修改。
- 輸出資料夾：**編輯者**（用建立並丟棄一個 0 位元組檔案來實證）。
- 一次性 OAuth 同意範圍包含：讀寫這張試算表、讀寫/建立/刪除你的 Drive 檔案、
  建立 Google 文件、連線到外部服務（呼叫 `RECORD_URL`）、在對話框顯示第三方內容。
- `RECORD_URL` 那個部署必須維持 **執行身分=我 / 存取權=任何人**。收緊了的話，這支程式抓回
  來的會是 Google 登入頁，而它會明確指出這個原因和修法。

## 4. 重新部署的規矩

這一節只適用於**兩支網頁應用程式**（Config、ConfigWithSubmit）。
**`Report.gs` 永遠不需要部署**——存檔、重新載入試算表，就是它的「上線」。

### 每次改完程式的唯一正確動作

1. Ctrl+S 存檔。**存檔不是上線。** 已部署的 `/exec` 還在服務上一次部署的版本。
2. 「部署」→「**管理部署作業**」。
3. 對**既有那一筆**部署點**鉛筆（編輯）**。
4. 「版本」下拉選「**新版本**」。
5. 在**同一個視窗**順手確認：**執行身分 = 我**、**具有存取權的使用者 = 任何人**。
6. 按「部署」。
7. 把對話框顯示的 `/exec` 和檔案裡的常數**逐字元**比對。**別用眼睛比**：開一張空白試算表，
   A1 貼對話框那一串、A2 貼檔案裡那一串、A3 打 `=EXACT(A1,A2)`，必須顯示 `TRUE`。
   - ConfigWithSubmit → `Start.dc.html` 第 210 行 **和** `Analysis.html` 第 163 行，
     開頭應為 `AKfycbzilnn3…`
   - Config → `Start.dc.html` 第 202 行，開頭應為 `AKfycbwIoR80…`
8. 回到「管理部署作業」，確認清單裡**仍然只有一筆**網頁應用程式部署。

### 絕對不要按「新增部署作業」

「新增部署作業」會鑄造一個**全新的 `/exec` 網址**，把你的修正放在那個新網址上，而
`Start.dc.html`／`Analysis.html` 還指著舊網址——**舊網址會永遠繼續服務舊程式碼，沒有任何
錯誤、沒有任何警告**。症狀是「我改了、部署了，行為幾天都沒變」。
本專案已經被這個動作咬過一次。

**已經按錯了怎麼辦**：管理部署作業 → 對**新增的那一筆**點 `⋮` → **封存**
（Apps Script 只提供「封存」，沒有「刪除」；封存後它就不再出現在清單裡）→
再對**原本那一筆**重做「鉛筆 → 版本：新版本 → 部署」。
⚠️ 別封存錯一筆：要留下的是網址跟 `Start.dc.html`／`Analysis.html` 裡那一串相同的那一筆，
封存前先用上面的 `=EXACT()` 確認。

### 執行身分／存取權錯了，在評核官眼裡長什麼樣

| 設定 | 評核官看到什麼 | 你自己看到什麼 |
|---|---|---|
| 存取權 = 「僅限自己」或「任何知道連結的 Google 使用者」 | 手機停在「載入中」然後載入失敗。Google 對未登入的 `fetch()` 回的是一頁 HTML 登入畫面，程式無法解析 | 你自己的瀏覽器一切正常（因為你登入了） |
| 執行身分 = 「存取網頁應用程式的使用者」 | 每個人（除了你）都看到「無法開啟設定試算表，請確認檔案權限。」 | 正常 |
| 存取權正確、紀錄表只有檢視權限 | 題目完全載入正常，**按下送出才失敗** | 不開 JSON 根本看不出來 |

**自己驗證的方法**：把裸 `/exec` 貼進一個**無痕視窗**（或登出 Google 的瀏覽器）。
必須得到 JSON，不是登入頁。

## 6. 換一家新醫院／新演習時，哪些要重做

### 6.1 同一家醫院、新增一場演習（例如 2026b）

**完全不用重做**：不用改程式、不用重新部署、不用重建任何 Apps Script 專案。

| 要做 | 怎麼做 |
|---|---|
| 建這一場的設定表（或沿用同一張） | 新一場如果題目不同，複製一份 演習評核_設定，改內容 |
| 建這一場的紀錄表 | **一定要新的紀錄檔案**（或至少不同的 `紀錄分頁名稱`）：兩列 `啟用=Y` 共用同一個 `紀錄試算表ID`＋`紀錄分頁名稱` 會讓**兩列都無效** |
| 註冊表加一列 | `醫院代號` 用**同一個**（`wanfang-7f3a2c`）、`演習代號` 新的（`2026b`）、填兩個 ID、`啟用=Y`。新的那場要當預設就把 `預設演習` 從舊列搬到新列 |
| `分析金鑰` | **同一家醫院的不同演習可以共用**同一把金鑰（健全性規則只禁止跨醫院共用） |
| 等 2 分鐘 | 註冊表快取 120 秒 |
| 發連結 | `Start.dc.html?t=wanfang-7f3a2c&ex=2026b`、`Analysis.html?t=wanfang-7f3a2c&ex=2026b&key=…` |
| 要出報告的話〔推論，報告功能從未實際跑過〕 | 把 `Report.gs` 專案的 `REPORT_EXERCISE` 改成 `2026b`（⚙ 專案設定 → 指令碼屬性）。如果新一場用的是**另一張**設定試算表，報告腳本就得繫結在那一張上，也就是一個**新的**容器繫結專案，見 6.2 |

**驗證**：`?t=wanfang-7f3a2c&ex=2026b` 的設定 JSON 要回 `"tenantSource":"registry"` 和
`"exercise":"2026b"`，而且 `orgName`／題目是這一場的。

### 6.2 新增一家醫院

| 要重做 | 不用重做 |

4. 用新醫院的金鑰去打舊醫院的 → 必須 `unauthorized`。
