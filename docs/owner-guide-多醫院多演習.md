# 多醫院 / 多演習操作手冊（業主用）

> 對象：負責開新演習、發連結、看報告的人。不需要會寫程式。
> 需要工程師的只有兩件事：**第一次貼上新版 Apps Script 程式碼並重新部署**，
> 以及**把註冊表的檔案 ID 填進程式裡那一行**（見 §3 步驟 3）。之後新增醫院、
> 新增演習、換金鑰、結束演習，全部只要改試算表。

---

## 0. 現在（還沒建註冊表時）是什麼狀態

程式裡有一行 `REGISTRY_SPREADSHEET_ID = '';`（空字串）。**空字串 = 整個註冊表機制
關閉**，系統完全照今天的方式運作：

- 評核單連結不帶任何參數 → 讀程式裡寫死的那一份設定試算表、寫進那一份紀錄試算表。
- 分析頁連結不帶任何參數 → 用程式裡那把 `ANALYSIS_KEY`。
- 就算有人在連結後面加了 `?t=xxx`，也**完全沒有作用**（不會報錯、不會換資料）。
  這是刻意的：如果連結已經發出去了而註冊表還沒建好，不能讓演習當天整場掛掉。

> **所以：你可以先把新版程式部署上去，什麼都不做，系統行為一模一樣。**
> 等真的要接第二家醫院或第二場演習時，再照 §3 建註冊表。

---

## 1. 租戶註冊表是什麼

一份新的 Google 試算表，檔名建議叫「**演習評核_租戶註冊表**」，裡面只要一個分頁，
分頁名稱必須是「**租戶註冊表**」。

它的角色是**總機**：一列 = 一場演習，記著「這一場要用哪一份設定檔、哪一份紀錄檔、
哪一把分析金鑰」。系統收到一條帶 `?t=`／`?ex=` 的連結時，就來這裡查該走哪一對檔案。

重點觀念：

| 觀念 | 說明 |
|---|---|
| **一場演習 = 一列 = 自己的兩份試算表** | 設定檔（題庫、代號、評分標準）跟紀錄檔（分數）都各自獨立。這是「去年的 1-1 不會被今年的 1-1 蓋掉」的根本原因。 |
| **代號不是檔案 ID** | `醫院代號`／`演習代號` 只是查表用的鑰匙。程式**永遠不會**拿代號去開檔案，檔案 ID 只能從註冊表這一列讀出來。 |
| **醫院代號要不好猜** | 用 `wanfang-7f3a2c` 而不是 `wanfang`。評核單那支網址沒有任何密碼保護，代號好猜等於別人可以一個一個試出其他醫院的題庫跟代號名冊。 |
| **註冊表只有你看得到** | 評核官手機抓到的資料裡，永遠不會出現任何檔案 ID、任何金鑰、任何註冊表內容。 |
| **改註冊表最多等 2 分鐘生效** | 註冊表有 120 秒快取。要立刻生效見 §7。設定試算表則**完全沒有快取**，改一格、手機重整就生效，跟今天一樣。 |

## 2. 欄位一覽（含目前測試環境的範例列）

欄位順序隨便放，**程式是比對標頭文字，不是比對欄位位置**。欄名可以用括號裡的任一個別名。

| 欄名（別名） | 必填 | 意義 | 範例值 |
|---|:--:|---|---|
| `醫院代號`（`機構代號`） | ✅ | 不可猜的機構 slug，對應連結裡的 `?t=`。只接受**小寫英數字、`-`、`_`，最多 32 字，開頭必須是英數字**。 | `wanfang-7f3a2c` |
| `演習代號`（`場次代號`） | ✅ | 同一家醫院的第幾場，對應連結裡的 `?ex=`。格式同上。**不要用 `2026-01` 這種「數字-數字」寫法**，Google 試算表會自動把它變成日期，程式會直接判這一列無效並告訴你原因。用 `2026a`、`2026b` 最安全。 | `2026a` |
| `顯示名稱`（`名稱`） | | 給人看的標題。會出現在分析頁的網頁標題、頁首大標、CSV 檔名上。留空就自動退回用設定檔裡的「機構名稱」。 | `萬芳醫院急救站 2026 上半年` |
| `設定試算表ID`（`設定檔ID`） | ✅ | 這一場專屬的「演習評核_設定」檔案 ID（網址 `/d/` 和 `/edit` 中間那一長串）。 | `1yiZDnbEFNHddzlTMWaz-bBgI0IvRWXMJ0H3WplyPJDk` |
| `紀錄試算表ID`（`紀錄檔ID`） | ✅ | 這一場專屬的「演習評核_紀錄」檔案 ID。**兩場演習絕對不要共用同一份紀錄檔**（除非照下一欄分成不同分頁）。 | `1jD6DXmPgTV9664XoIveD_cqNQd9V8vq6aM7EtMoI6FM` |
| `紀錄分頁名稱`（`紀錄分頁`） | | 留空 = `評核紀錄`。只有在「兩場演習硬要共用一份紀錄檔」時才填不同值（例如 `評核紀錄_創傷`）。 | `評核紀錄` |
| `分析金鑰`（`金鑰`） | ✅ | 看報告用的密碼，自己產生一串 32 字亂數。**換金鑰 = 改這一格，不用重新部署。** | 見下方 ⚠️ |
| `啟用`（`啟用中`） | | `Y`／留空 = 開放評核。填 `N`／`否`／`停用` = 這場已結束：評核單打不開、送不出，**但報告還看得到**（演習結束後才要做報告）。 | `Y` |
| `開放送出起`（`送出開始`） | | 送出時間窗起點，留空 = 不限。只擋「送出」，**不擋「打開看題目」**（評核官可以提早開表單讀題）。 | `2026/10/06 08:00` |
| `開放送出迄`（`送出結束`） | | 時間窗終點，留空 = 不限。超出範圍時評核單上的送出鈕會變灰並顯示原因，不會先收下分數再丟掉。 | `2026/10/06 18:00` |
| `預設演習`（`預設`） | | 每家醫院**只能有一列**填 `Y`。只給 `?t=` 沒給 `?ex=` 時用這一列。零列或兩列以上都會報錯，系統不會替你猜。 | `Y` |
| `scenePrefix`（`情境前綴`） | | 留空 = `SCENE`。你的最底層項目如果叫「SCENE A1」，編號徽章就會顯示「A1」。改用別的命名（例如「單元 A1」）就把這格填 `單元`。 | `SCENE` |
| `檔案擁有者`（`擁有者`） | | **純備忘，程式完全不讀它。** 記下這對檔案是哪個 Google 帳號擁有的，將來權限出問題時不用猜。 | `charleslin2003@gmail.com` |

> ⚠️ **`分析金鑰` 這一格要填什麼**：第一列（也就是把今天這一場「搬」進註冊表的那一列）
> **必須填現在 `Analysis.html` 裡那把金鑰的原值**，否則今天已經發出去的分析頁連結會
> 立刻失效。那個值在 `Analysis.html` 檔案開頭 `const ANALYSIS_KEY = '…'` 那一行，
> 直接複製貼過來。之後新增的每一列都應該各自產生一把新的亂數。

### 目前測試環境的完整範例列

| 醫院代號 | 演習代號 | 顯示名稱 | 設定試算表ID | 紀錄試算表ID | 紀錄分頁名稱 | 分析金鑰 | 啟用 | 開放送出起 | 開放送出迄 | 預設演習 | scenePrefix | 檔案擁有者 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `wanfang-7f3a2c` | `2026a` | 萬芳醫院急救站 2026 上半年 | `1yiZDnbEFNHddzlTMWaz-bBgI0IvRWXMJ0H3WplyPJDk` | `1jD6DXmPgTV9664XoIveD_cqNQd9V8vq6aM7EtMoI6FM` | `評核紀錄` | （照抄 `Analysis.html` 裡 `ANALYSIS_KEY` 的值） | `Y` | （留空） | （留空） | `Y` | `SCENE` | charleslin2003@gmail.com |

舊連結不會失效。發布任何新連結之前，請用 §8 的自我檢測把兩條路都跑一次確認。

## 3. 第一次建立註冊表（只做一次）

1. 新開一份 Google 試算表，檔名「演習評核_租戶註冊表」。
2. 把唯一那個分頁改名成「**租戶註冊表**」，第一列照 §2 打上欄名（至少五個必填欄）。
3. 複製網址裡的檔案 ID，**請工程師**把它填進 `apps-script/ConfigWithSubmit.gs` 的
   `REGISTRY_SPREADSHEET_ID = '';` 那一行，然後重新部署（部署步驟見 §13）。
4. 照 §2 的範例列填**第一列**（指向現有的那兩份試算表）。
5. 跑一次自我檢測（§8），確認「✅ 設定檔可讀、✅ 紀錄檔可寫」。
6. 這一步做完之後，**以後都不用再動程式**。

## 4. 新增一家醫院

1. **複製兩個範本檔**：在雲端硬碟對現有的「演習評核_設定」和「演習評核_紀錄」各按
   「檔案 → 建立副本」，改名成那家醫院的版本（例如「演習評核_設定_○○醫院_2026上」）。
2. **把紀錄檔的舊資料列刪掉**（只留標頭列）。設定檔的題庫則照那家醫院的架構改。
3. **確認權限**：執行 Web App 的那個 Google 帳號，必須對設定檔有「**檢視者**」、
   對紀錄檔有「**編輯者**」。少了編輯權，評核官按送出會失敗。
4. **註冊表加一列**：
   - `醫院代號`：自己想一個不好猜的，例如 `地名縮寫-6碼亂數`（`taoyuan-91c4de`）。
     **不要用 `taoyuan` 這種一猜就中的字。**
   - `演習代號`：`2026a`。
   - `設定試算表ID` / `紀錄試算表ID`：貼上步驟 1 那兩個檔案的 ID。
   - `分析金鑰`：產生一把**新的** 32 字亂數（不要跟別家共用，程式會直接擋）。
   - `啟用` = `Y`，`預設演習` = `Y`。
5. **跑自我檢測**（§8），確認兩個 ✅。
6. **發兩條連結**（§10）。

## 5. 同一家醫院新增第二場演習

跟 §4 幾乎一樣，差別只有三點：

- `醫院代號` **沿用**同一個（這樣「過去演習」清單才看得到同一家的歷史場次）。
- `演習代號` 換新（`2026b`）。
- `分析金鑰` 可以跟同院前一場**共用同一把**（一家醫院一把儀表板金鑰），也可以各場
  一把。**但絕對不能跟別家醫院共用** —— 同一把金鑰出現在兩個不同 `醫院代號` 底下時，
  那些列會全部被判無效，因為那等於 A 院改一下網址就能看 B 院的報告。

**還有一件事**：把舊那一場的 `預設演習` 清空，只留新場次那一列是 `Y`
（兩列都是 `Y` 會讓只帶 `?t=` 的連結直接報錯，系統不會替你猜）。

> **替代做法（兩場共用一份紀錄檔）**：如果真的不想多開檔案，可以兩列填同一個
> `紀錄試算表ID`，但 `紀錄分頁名稱` 必須不同（`評核紀錄_創傷` / `評核紀錄_大量傷患`），
> 而且那個分頁要先在檔案裡建好、標頭列照抄。**（紀錄試算表ID + 分頁名稱）重複的列
> 會被全部判無效** —— 這是故意的硬擋：那正是「複製了一列但忘記換紀錄檔」害兩場演習
> 互相覆蓋分數的唯一入口。

## 6. 結束一場演習

把那一列的 `啟用` 改成 `N`，**就這樣**。

| 改成 N 之後 | 結果 |
|---|---|
| 評核官打開評核單 | 看到「這場演習已結束，不再開放評核。」 |
| 評核官按送出 | 被拒絕，同一句話 |
| 你打開分析頁 | **照常可以看**（報告本來就是演習結束後才做） |
| 「過去演習」清單 | 列出來、標示為「已結束」 |
| 註冊表的重複檢查 | 這一列不再參與（所以明年複製一列重辦時不會跟它打架） |

另一種做法是用 `開放送出起`／`開放送出迄` 預先設好時間窗，演習當天時間一到自動開、
時間一過自動關，不用人手改。兩者可以同時用。

## 7. 換分析金鑰（不用重新部署）

1. 在註冊表找到那一列，把 `分析金鑰` 改成新的一串亂數。
2. 跑一次 `action=flush`（下一段）讓它立刻生效，或等 2 分鐘。
3. 把新的分析頁連結（`…?t=…&ex=…&key=新金鑰`）重新發給該看的人。舊連結立刻失效。

**立刻生效（清掉註冊表快取）**：在瀏覽器網址列打

```
<RECORD_URL>?action=flush&adminKey=<你的管理金鑰>
```

回 `{"ok":true,"flushed":["reg:v2"]}` 就是清好了。這個動作**只**清註冊表快取，
不會碰送出去重的那份快取（碰了會讓正在重試的送出變成重複列）。

> **管理金鑰（ADMIN_KEY）**是另一把金鑰，只給 `action=selftest` 和 `action=flush` 用。
> 它**不寫在任何上架的網頁檔案裡**，只能由你自己打在網址列。程式裡預設是空字串 =
> **這兩個功能停用**；要用的話請工程師在 `ConfigWithSubmit.gs` 的 `ADMIN_KEY = '';`
> 填一串亂數並重新部署。**不要跟 `分析金鑰` 用同一串。**

## 8. 自我檢測 `action=selftest`：怎麼跑、答案怎麼讀

新增完一場演習（或任何時候懷疑權限有問題）就跑它。在瀏覽器網址列打：

```
<RECORD_URL>?action=selftest&adminKey=<管理金鑰>&t=<醫院代號>&ex=<演習代號>
```

（`t`／`ex` 可以省略，省略就是檢查「不帶參數時會用到的那一組」。**新增完一場演習後，
建議兩條路都各跑一次**：帶參數的那條和不帶參數的那條。）

回來的是一段 JSON。先看 `messages` 那一串中文，那是給人看的：

| 看到的訊息 | 意思 / 該做什麼 |
|---|---|
| `✅ 設定檔可讀：<檔名>` | 設定試算表打得開，而且檔名就是你以為的那一份。**檔名不對 = 註冊表那一列的 ID 貼錯了。** |
| `✅ 紀錄檔可寫` | 真的對紀錄檔做過一次無害的寫入測試（寫一個隱藏標記再刪掉，**不會新增任何一列、不會動任何一格**）。 |
| `⚠️ 紀錄檔無法寫入：…` | 權限不足。到紀錄檔按「共用」，把執行 Web App 的那個帳號加成「編輯者」。 |
| `⚠️ 設定檔缺少分頁：…` | 那幾個分頁名稱打錯或被刪了（需要：演習資訊／人員代號／評分標準／項目與問題／對應指標）。 |
| `⚠️ 註冊表第 N 列無效：<原因>` | 第 N 列被判無效，**整列失效**，走到那一列的連結會收到「註冊資料有問題」。原因就寫在後面，照字面修。 |
| `⚠️ 註冊表無法使用，已退回程式內建的那一組試算表：…` | 註冊表打不開／分頁名稱不對／一列資料都沒有。這時系統**不會掛**，會退回用程式裡寫死的那一組，但所有 `?t=` 都失去作用。 |
| `尚未設定租戶註冊表…` | 正常，代表還在 §0 的狀態。 |
| `尚未設定管理金鑰（ADMIN_KEY），自我檢測未啟用。` | 見 §7 最後那段，請工程師填 `ADMIN_KEY` 並重新部署。 |

其他欄位快速對照：

- `tenantSource`：`registry` = 這條連結真的從註冊表查到了一列；`fallback` = 用的是程式
  內建那一組。**新增完一場演習後，帶參數那條一定要是 `registry`。**
- `config.codeCount` / `criteriaCount` / `leafCount` / `questionCount`：代號幾個、評分
  標準幾級、最底層項目幾個、題目幾題。**數字跟你的試算表對不起來就是欄名打錯了。**
- `record.headerColumns`：紀錄表第一列實際讀到的欄名。想確認「觀察紀錄」那一欄有沒有
  被認出來，就看它在不在 `presentOptional` 裡。
- `record.missingRequired`：紀錄表缺了必要欄（問題ID／分數／人員代號／送出時間）。
  有東西 = 送出一定會失敗。

> **自我檢測的回傳內容刻意只有「檔名、分頁名、欄名、數量」**，不含任何試算表 ID、
> 任何金鑰、任何人員代號、任何題號、任何分數。所以它可以安心截圖給別人看。

## 9. 為什麼某一列會被判「無效」

程式每次讀註冊表都會跑五條檢查。**被判無效的列等於不存在**：走到它的連結會收到
「這場演習的註冊資料有問題，請聯絡系統管理者。」，**絕對不會改讀別一列的資料**，
也不會偷偷退回程式內建那一組。具體原因只出現在 `action=selftest`。

| # | 規則 | 為什麼要這麼嚴 |
|---|---|---|
| 1 | `醫院代號`+`演習代號` 重複 → **那一組全部無效**（不是「第一列獲勝」） | 否則「哪一列說了算」要看誰排在上面，同一條連結今天明天看到不同資料 |
| 2 | `紀錄試算表ID`+`紀錄分頁名稱` 重複 → **那一組全部無效** | 兩場演習寫進同一張表，同樣的題號會互相覆蓋分數 —— 這是整個系統最嚴重的那個老問題，必須硬擋 |
| 3 | 同一把 `分析金鑰` 出現在**不同** `醫院代號` 底下 → 共用那把金鑰的列全部無效 | 否則 A 院只要改一下網址的 `?t=` 就能看 B 院的報告。**同一家醫院的不同場次共用一把金鑰是允許的** |
| 4 | 任一必填欄空白 → 只有那一列無效 | — |
| 5 | 代號格式不合、檔案 ID 格式不合、時間格式讀不懂 → 只有那一列無效 | 格式不合的代號如果被當成檔案 ID 用，整個系統就變成「任意檔案讀取代理」 |

規則 1、2 **只比對 `啟用=Y` 的列**（所以封存的舊列不會跟新列打架）；規則 3 **比對全部
列**（封存了，那把金鑰還是能看報告，仍然是有效憑證）。

常見原因對照：

- `演習代號 被試算表判讀成日期，請把該格設成純文字格式` → 你填了 `2026-01`。
  把那一格「格式 → 數值 → 純文字」再重打，或直接改成 `2026a`。
- `醫院代號 格式不合（只允許小寫英數、- 與 _，最多 32 字）` → 有大寫、中文或空格。
- `紀錄試算表ID+分頁名稱 與第 N 列重複，兩場演習會互相覆蓋分數` → 複製列時忘了換紀錄檔。

## 10. 連結怎麼發

| 給誰 | 連結長相 |
|---|---|
| 評核官（評核單） | `…/Start.dc.html?t=<醫院代號>&ex=<演習代號>` |
| 評核官（該院只有一場、且那列 `預設演習=Y`） | `…/Start.dc.html?t=<醫院代號>` |
| 你自己（分析儀表板） | `…/Analysis.html?t=<醫院代號>&ex=<演習代號>&key=<分析金鑰>` |
| 你自己（直接開列印報告） | 上面那條再加 `&view=report` |

- **評核官那條連結裡永遠不會有任何金鑰**，也不該有。
- **分析頁那條連結等於密碼**，只給該看的人，不要貼進群組。
- 按下分析頁的「產生報告」之後，網址列的 `?key=` 會被自動清掉（這樣用瀏覽器列印時
  頁尾印出來的網址不會把金鑰印在紙上）。代價是**那之後按重新整理就要重新貼一次連結**。

## 11. ⛔ 鐵則：演習開始到報告歸檔之間，不要編輯設定試算表

**從第一位評核官打開連結，到那一場的報告做完歸檔為止，請不要動「演習評核_設定」
這份檔案的任何一格。** 下一場的題庫請改在**新複製出來的那一份**上。

兩個具體後果：

1. **飛行中的送出會失敗、分數會不見。** 送出時程式會拿「**當下**」的設定表來驗證：
   人員代號在不在名單裡、項目名稱找不找得到、題號對不對得上。評核官手機在收訊不好
   的地方會自動重試三次 —— 如果你剛好在這幾秒之間改了項目名稱或題號，那次重試會被
   以「未知的項目名稱」「未知的問題ID」拒絕，而他已經填好的那一頁分數就沒了。
   （對應程式：`ConfigWithSubmit.gs:740-760` 的白名單比對。）
2. **已經發出去的報告標籤會被回頭改寫。** 分析頁上的「情境階段／測試情境／評核潛能／
   4S 元素／指標」這些標籤，**不是送出當時存起來的，是看報告的那一刻才去設定表對照
   出來的**。你為了下一場把題庫換掉，上一場那份已經印出來的報告再打開一次，標籤就跟
   紙本對不上了，而且沒有任何警告。（對應程式：`ConfigWithSubmit.gs:945-1045` 讀取時
   的對照邏輯。）

> **解法正是本手冊在講的事**：下一場 = 複製兩份新檔案 + 註冊表加一列。
> 這樣「準備下一場」從此不再需要碰上一場的任何檔案。

另外，紀錄試算表如果補上了「測試情境／評核潛能／4S 元素／評核題目／指標代號」這幾個
選填欄（見 `README.md`），送出當時就會把標籤寫死在那一列，後果 2 就會自動消失。
報告的「資料品質」章節會明白印出「本報告標籤取自送出當時快照 N 題／讀取時對照 M 題」，
讓看報告的人知道自己看的是哪一種。

## 13. 重新部署步驟（需要工程師，只在改程式碼時做）

1. Apps Script 編輯器 → 貼上新版 `ConfigWithSubmit.gs`。
2. **部署 → 管理部署作業 → 編輯（鉛筆）現有那一個部署**
   → 版本選「**新版本**」→ 部署。
3. ⚠️ **不要選「新增部署作業」** —— 那會產生一條**不同**的 `/exec` 網址，
   舊網址還活著但不會更新，症狀是「程式明明改了卻完全沒生效」。
4. 確認「執行身分 = 我」「誰可以存取 = 任何人」。執行身分設錯會讓每支評核官手機
   被要求登入 Google。
5. 部署後**先用手機實際跑一次完整送出**，再公布連結。
6. 要回滾就在同一個對話框把版本切回上一版。

## 14. 產生正式評核報告（試算表選單 → Google 文件 → PDF）

> 對象：要把演習結果做成一份可以進醫院文管、可以帶進品質委員會的報告的人。
> 全程在「演習評核_設定」這份試算表裡操作，**不需要工程師、不需要重新部署**。
>
> ### ⚠️ 先講最重要的一句：這段程式到今天為止，沒有任何人執行過
>
> 它是對著後端回傳的資料格式寫出來的，但**沒有人能在交付前真的跑它** —— Apps Script
> 只能在你的 Google 帳號裡跑。所以**你的第一次產生報告，就是這支程式的第一次測試**。
> 程式是照「寧可印醜、不要出錯」的原則寫的：任何一個不確定的功能（雷達圖、自動目錄、
> 圖片輸出）都會先試、失敗就自動改用表格或長條圖，並在報告的「附錄C」寫明它改用了什麼。
> 請務必照 **§14.9 的第一次執行檢查清單**跑一次，並把附錄C 那幾行回報回來。
>
> 請**不要**挑演習當天或委員會前一天做第一次測試。先用現有的測試資料跑一次。

### 14.0 它跟分析頁的「產生報告」按鈕差在哪

| | 分析頁的「產生報告」（列印版） | 這一節講的選單報告 |
|---|---|---|
| 怎麼開始 | 開分析頁網址 → 按按鈕 → Ctrl+P | 開設定試算表 → 上方選單 |
| 產出 | 瀏覽器列印出來的 PDF | **可編輯的 Google 文件 ＋ PDF** |
| 頁碼／目錄／頁首院徽 | **做不到**（Chrome 只能印它自己的頁尾，而那個頁尾會把含金鑰的網址印在紙上） | **有**，而且版面由你自己在範本文件裡決定 |
| 要不要先設定 | 不用 | 要（§14.1–§14.4，只做一次） |
| 定位 | 內部快速檢視 | **可歸檔的品質紀錄、交付用** |

兩者的數字完全一樣，都是向同一個後端要同一份分析結果。

### 14.1 安裝（只做一次，不需要部署）

1. 打開「**演習評核_設定**」這份試算表（**一定要是這一份**，因為報告會在它上面建立
   「報告快照」工作表，也會從它讀「評分標準」）。
2. 上方選單 **擴充功能 → Apps Script**。會開新分頁。
3. 左邊看到預設的 `Code.gs`。把裡面原有的內容全選刪掉，貼上 `apps-script/Report.gs`
   的全部內容。（想保留檔名也可以：**檔案 → 新增 → 指令碼**，命名 `Report`，貼進去。）
4. 左邊 **檔案 → ＋ → HTML**，檔名打 **`ReportDialog`**（**大小寫要一模一樣，不要加 .html**），
   把裡面預設的內容刪掉，貼上 `apps-script/ReportDialog.html` 的全部內容。
5. 按 **💾 儲存專案**（或 Ctrl+S）。
6. 回到試算表那個分頁，**重新整理頁面（F5）**。
7. 上方選單列應該多出一個「**演習評核報告**」。

> **為什麼不用部署？** 這支程式是「容器綁定」在試算表上的，它不是網站、沒有網址、
> 外面的人碰不到它，所以沒有「部署」這個步驟 —— 存檔、重整試算表就生效。
> 這跟 §13 那個會讓人選錯選項就整場掛掉的「重新部署 Web App」是**完全不同的兩件事**。
> 這也是當初選這條路的全部理由：報告功能**一行都沒有動到**評核單與分析頁的那支程式。
>
> 看不到選單時：(a) 確認有按儲存；(b) 確認有重新整理試算表；(c) 確認貼的位置是
> 「擴充功能 → Apps Script」而不是另外開一個獨立的 Apps Script 專案。

### 14.2 第一次點選單時會看到的 Google 授權畫面（正常現象）

第一次點「演習評核報告」底下任何一個項目時，Google 會跳出一連串授權畫面。**這是正常的**，
因為這支程式要替你讀試算表、建立文件、上網抓資料。照這個順序按：

1. 「**需要授權**」→ 按「**確定／繼續**」。
2. 選擇你的 Google 帳號（**用會擁有這些報告檔案的那個帳號**）。
3. 出現 **「Google 尚未驗證這個應用程式」／「未經 Google 驗證」** 的警告畫面。
   **這是預期中的**：這個警告只代表「這段程式是你自己貼上去的，沒有送交 Google 審核」，
   不代表有病毒。自己寫的試算表巨集一律會長這樣。
   → 點左下角小字「**進階**」→ 再點「**前往〈專案名稱〉（不安全）**」。
4. 最後一頁列出它要的權限（查看與管理試算表、建立與管理 Google 雲端硬碟檔案、
   連線到外部服務）→ 按「**允許**」。
5. 授權畫面關掉後，**選單項目可能要再點一次**才會真的執行。

之後就不會再問了。只有換帳號、或程式要用到新的權限時才會重來一次。

### 14.3 設定「指令碼屬性」（只做一次）

金鑰**刻意沒有寫在程式裡**（程式碼會被複製、轉寄、存進版本控制，金鑰一旦進去就收不回來），
所以要你自己填在一個只有你看得到的地方。

**位置：擴充功能 → Apps Script → 左側 ⚙ 專案設定 → 往下捲到「指令碼屬性」
→ 新增指令碼屬性 → 填一組「屬性（鍵）」與「值」→ 最後按「儲存指令碼屬性」。**

| 屬性（鍵，請原字複製） | 必填？ | 值要填什麼 |
|---|---|---|
| `REPORT_ANALYSIS_KEY` | **必填** | 這一場演習的**分析金鑰**。還沒建註冊表（單一演習模式）時＝工程師給你的那把分析金鑰，也就是分析頁網址 `?key=` 後面那一串；已經建了註冊表就填**那一列的「分析金鑰」**。 |
| `REPORT_API_URL` | **必填** | 後端網址，以 `https://script.google.com/macros/s/…/exec` 結尾的那一條。要用**有 `action=analysis` 的那一支**（分析頁用的那條網址，去掉 `?` 後面全部）。⚠️ 不能是 `/dev` 結尾，也不能是 Apps Script 編輯器的網址。 |
| `REPORT_TEMPLATE_DOC_ID` | **必填** | §14.4 做好的範本文件的檔案 ID：打開範本，看網址 `https://docs.google.com/document/d/` 與 `/edit` **中間**那一段。 |
| `REPORT_OUTPUT_FOLDER_ID` | 選填 | 報告要放的雲端硬碟資料夾 ID（網址 `/folders/` 後面那一段）。不填就放在設定試算表所在的資料夾。 |
| `REPORT_TENANT` | 選填 | 醫院代號。**只有已經建了租戶註冊表才填**；填了之後程式會要求後端回報的醫院代號完全相同，不同就拒絕產生。單一演習模式請**留空**。 |
| `REPORT_EXERCISE` | 選填 | 演習代號，規則同上。 |
| `REPORT_TIME_BUDGET_MS` | 選填 | 單次步驟的時間預算毫秒數，預設 `240000`。環境特別慢、常常產到一半停住時，可以改小成 `180000`，讓章節切得更碎。 |
| `REPORT_RUN_STATE` | **不要手動設** | 程式自己維護的執行紀錄。卡住時用選單的「重設產生狀態」清掉。 |

> `REPORT_TENANT` / `REPORT_EXERCISE` 是防呆用的：它擋的是「腳本綁在 A 院的設定表上，
> 金鑰卻把資料路由到 B 院」—— 那種錯誤產出的 PDF 會印著 A 院的封面和 B 院的分數，
> 而且看起來一切正常。
>
> 忘記設了哪些？選單 →「**設定說明（指令碼屬性）**」會列出全部鍵、意義與目前是否已設定。
> **已設定的金鑰只會顯示「已設定（已遮蔽）」，永遠不會把值印出來**（這個畫面常被截圖）。

### 14.4 做一份範本 Google 文件（只做一次，之後想改版面就改它）

**為什麼一定要有範本：** 程式操作 Google 文件的那套介面（`DocumentApp`）**沒有任何插入頁碼
的功能**。頁碼只能存在於 Google 文件的頁首／頁尾，而頁首／頁尾只能由人手動放。一份要歸檔的
品質紀錄沒有頁碼就不是歸檔文件 —— 這正是列印版出局的同一條理由。範本還順便讓「版面再美
一點」這件事永遠不需要找工程師：院徽、字型、邊距、標題樣式、簽核欄全部在範本裡。

**程式永遠不會寫入範本本身**，每次產生都是先複製一份再寫。

步驟：

1. 新建一份 Google 文件，命名例如「**演習評核報告_範本**」。
2. **插入 → 頁首和頁尾**：頁首放院徽／機構名，頁尾用「**插入 → 頁碼**」放頁碼。
3. 設定「**標題 1 / 標題 2 / 標題 3**」三個具名樣式的字型與大小
   （格式 → 段落樣式 → 標題 1 → 更新「標題 1」以符合）。程式附加章節時只會說
   「這是標題 2」，長什麼樣完全由這裡決定。順便設定邊距與內文字型。
4. **做封面**：把下面這些 token **原字打進去（含兩層大括號）**，程式會逐字替換掉。
   不需要的 token 不打就好，不會報錯。放在頁首／頁尾裡的 token 也會被替換。

| 封面 token | 會被換成什麼 | 例 |
|---|---|---|
| `{{機構名稱}}` | 機構名 | 臺北市立萬芳醫院 |
| `{{演習名稱}}` | 演習名稱 | 115年度大量傷患演習 |
| `{{演習主題}}` | 主題（與「類別」是不同欄位，不可互相代用） | 院內大量傷患收治與檢傷分流 |
| `{{演習類別}}` | 類別 | 桌上推演 |
| `{{演習日期}}` | 演習日期 | 2026/10/03 |
| `{{機構代號}}` | 醫院代號；單一演習模式會印「—（單一演習模式）」 | wanfang-7f3a2c |
| `{{演習代號}}` | 演習代號；同上 | 2026-01 |
| `{{評核官人數}}` | **只有人數，永遠不含任何代號** | 5 |
| `{{資料列數}}` | 原始列數與納入統計的題數 | 原始 101 列／納入統計 23 題 |
| `{{報告產生時間}}` | 產生時間 | 2026-10-06 15:42 (GMT+8) |
| `{{報告編號}}` | 本次執行的編號，是文件／PDF／快照三者的唯一關聯鍵 | R20261006-1542-7K3QD9 |
| `{{匿名模式}}` | 「已匿名（評核官 1…N）」或「⚠ 含可識別評核官代號」 | 已匿名（評核官 1…N） |

### 14.6 產生時要做的那個隱私選擇

對話框上有三個勾選框：

| 勾選框 | 預設 | 說明 |
|---|:--:|---|
| 附上觀察紀錄彙整（第十二章） | **已勾** | 質性內容是這份報告最有價值的部分。但**匿名化擋不住自由文字本身**：代號可以換成「評核官 3」，文字裡如果寫了「張護理長」，沒有任何程式手段能遮蔽。**分發前請人工看過這一章。** |
| 附上附錄B 原始評分資料（逐題 × 逐評核官） | 未勾 | 即使匿名，這仍是一張完整的個別評分矩陣，所以預設不附。 |
| 附上可識別的評核官代號（識別模式） | 未勾 | 勾了會**立刻跳出第二道確認**，寫明後果後才生效。 |

**預設是匿名的，而且匿名是整條流程的預設值**：所有評核官一律顯示「評核官 1」…「評核官 N」，
編號規則與分析儀表板完全一致（同一場演習的螢幕與紙本指的是同一個人）。
代號對照序號的那張表**不會印在報告的任何地方**。

要印出真正的人員代號必須同時滿足三件事：勾選該框、通過第二道確認、範本裡有
`{{SEC_評核官差異}}` 錨點。選了識別模式之後，封面的 `{{匿名模式}}` 會印出
「⚠ 含可識別評核官代號」、附錄C 也會記一筆 —— **報告必須自己說出自己是什麼**。

> 在十餘人的品管部門裡，人員代號等同可以還原到個人的假名。這個呈現方式當初是**刻意**
> 從分析儀表板上移除的。要用識別模式，請先確認已取得必要的同意，並依院內個資規範控管流通。
>
> 不管你怎麼勾，「**報告快照**」工作表**永遠不會寫入任何人員代號、任何逐評核官分數、
> 任何觀察紀錄原文**。這一條沒有開關 —— 識別資料只存在於那一份文件與 PDF 裡，
> 不會沉澱進你的試算表、長期累積成一份逐評核官資料集。

### 14.7 產出落在哪裡、要等多久

- 對話框會一章一章顯示進度、計時器、以及「警告與降級紀錄」。**不要關掉它。**
- 完成後對話框上會出現兩個連結：**開啟 Google 文件**、**開啟 PDF**。
- 檔案落在 `REPORT_OUTPUT_FOLDER_ID` 指定的資料夾，沒設就在設定試算表所在的資料夾。
- 檔名長這樣：`R20261006-1542-7K3QD9 臺北市立萬芳醫院 評核報告`，PDF 同名加 `.pdf`。
  產生中會暫時帶「（產生中）」後綴，完成時拿掉。
- **預估 30–90 秒**，題目多、圖多時更久。
- 產出的 Google 文件**是可以編輯的** —— 結論、建議、改善行動這些系統生不出來的內容，
  請直接在那份文件上補，然後自己另存 PDF。

**連按兩次「開始產生」不會蓋掉好的那一份。** 每一輪都是複製出一份**全新的文件**，
程式從不寫入任何既有的報告檔案；最壞的結果是兩份各自獨立的報告，不會是半份蓋掉一份。

### 14.8 產到一半停住、或超過時間了怎麼辦

Apps Script 單次執行有 6 分鐘上限，所以程式是**一段一段產**的，每段結束就把控制權交還給
對話框再發下一段。真的用完總預算時，它**不會無聲停住**，而是在三個地方自己說出來：

1. 文件第一頁保留「**草稿 — 產生未完成（本份報告尚未完成，請勿分發）**」橫幅；
2. 檔名帶「**（部分完成）**」後綴；
3. 「報告快照」工作表的「報告狀態」欄變成「**部分完成**」，附錄C／附錄D 列出被跳過的章節。

沒產完的章節會就地換成「（本節未產生：產生程序依時間預算中止）」。
**數字不會掉** —— 全部的統計值在開始寫文件之前就已經寫進「報告快照」了。

怎麼處理：

- **想要完整版** → 把範本裡「九、情境逐項分析」`{{SEC_情境}}` 或其他選用錨點先刪掉幾個，
  或把 `REPORT_TIME_BUDGET_MS` 改小（例如 `180000`），再產生一次（會做出一份**全新的**報告）。
- **不小心關掉對話框** → 選單「開啟上一份報告」把那份半成品找回來；
  要重新產生先點「**重設產生狀態**」（它不會刪掉任何檔案）。
- **說「報告正在產生中」但其實沒有** → 同樣用「重設產生狀態」。超過 15 分鐘沒進展的
  紀錄會自動被視為中斷。

### 14.9 ⭐ 第一次執行的檢查清單（請照這個順序，並把結果回報）

再說一次：**這支程式從來沒有被任何人執行過，你的第一次就是測試。** 請用現有的測試資料跑，
不要在演習當天或委員會前一天第一次跑。

1. 選單出現了嗎？（§14.1 第 7 步）
2. 先點「**檢查設定（不產生報告）**」。把每一項的 ✅/❌ 看完，有 ❌ 就照中文說明修，
   修完按「重新檢查」。**全部 ✅ 之前不要按產生。**
   特別看這幾項：「指令碼屬性」「報告範本」「必要章節錨點」「錨點位置」「輸出資料夾」
   「取得分析資料」「租戶身分比對」「設定檔名稱比對」「資料非空」「ICC(2,k) 本機驗算」
   「圖表能力探測」。
3. 再點「**產生評核報告…**」，**三個勾選全部維持預設**（匿名、附觀察紀錄、不附附錄B），
   按「開始產生」。看著進度跑完。
4. 打開產出的 **Google 文件**，確認這八件事：
   - 封面上**沒有任何殘留的 `{{…}}`**（有的話代表那個 token 在範本裡打錯字了）。
   - **頁尾有頁碼**（沒有的話是範本第 2 步沒做，不是程式的問題）。
   - 章節順序與你在範本裡排的錨點順序一致，刪掉的章節確實沒有出現。
   - 封面的「匿名模式」那一行寫「已匿名（評核官 1…N）」。
   - 全文搜尋你自己的某一個人員代號（例如 `A01`）—— **應該一個都找不到**。
   - 圖有沒有出來。**就算沒出來也不算失敗** —— 應該會看到一句「本節圖表無法在此環境產生
     （原因：…），已改以數值表呈現，數值與圖表完全相同」，數字還在。
   - **附錄C** 的「圖表能力探測結果」「ICC 驗算結論」「被跳過的章節」三行。
   - **附錄D** 列出的未涵蓋項目。
5. 打開 **PDF**，確認它不是空白、頁數與文件一致。
6. 回到試算表，看多出來的「**報告快照**」工作表：應該有這一輪的那幾列，
   「報告狀態」欄是「**完成**」，而且**整張表裡找不到任何人員代號、任何觀察紀錄文字**。
7. 拿報告上的幾個數字（總平均、ICC(2,k)、覆蓋率）去跟**分析儀表板**對一次，
   **必須完全相同**。不同就是 bug，請回報。

**請回報這幾項**（這是這支程式唯一的實機驗證來源）：
附錄C 的「圖表能力探測結果」整行、「ICC 驗算結論」整行、對話框「警告與降級紀錄」裡的全部內容、
整個流程花了幾秒、以及任何一個你看不懂的錯誤訊息（請照原文貼回來）。

### 14.10 「報告快照」工作表是什麼，為什麼不要刪它

產生報告時會在設定試算表上建立／附加一個「**報告快照**」工作表。它**只會新增列，
永遠不會清空、不會覆寫既有的列**。每一列是「某一次報告裡的某一題」的彙總值：
報告編號、產生時間、報告狀態、機構代號、演習代號、分組、問題ID、階段、項目名稱、情境編號、
測試情境與目標、指標、評核潛能、4S 元素、評核題目、評核人數、平均、標準差、未觸發數、標籤來源。

四個用途：

1. **把標籤凍結起來** —— 報告裡每一個標籤與數字都在那一刻被凍住。你下個月改「項目與問題」
   或「對應指標」，不會再回頭改寫這份已經發出去的報告的依據（§11 的後果 2）。
2. **它是「與前次演習比較」唯一可能的資料來源** —— 這一次還不能比較，但從這份報告開始，
   每一場都留下可比對的基準，下一場就能做。
3. PDF 不能用程式讀，報告快照是「這份 PDF 說了什麼」的唯一機器可讀副本，
   「報告編號」把文件／PDF／快照三者串起來。
4. 你不開儀表板，也能直接在試算表上用篩選核對任何一題。

後端（評核單與分析頁）**從不讀「報告快照」和「_報告暫存」**，所以多這兩個分頁對評核官
那一端與分析頁是零影響。「_報告暫存」是畫圖用的隱藏暫存分頁，不要刪、也不用管它。

### 14.11 常見訊息對照

| 看到的訊息 | 意思與處理 |
|---|---|
| 指令碼屬性缺少 `REPORT_…` | §14.3 那個鍵沒設或打錯字。鍵名的大小寫、底線都要一模一樣。 |
| 找不到報告範本，或執行報告的帳號沒有這份文件的權限 | `REPORT_TEMPLATE_DOC_ID` 貼錯（貼成整條網址，或貼到別份檔案的 ID），或範本沒有分享給現在這個帳號。 |
| 缺少必要章節錨點 | 範本少了六個必要錨點之一，訊息會逐一指名。回 §14.4 補上。 |
| 錨點不是單獨一個最上層段落 | 錨點被放進表格／頁首／清單了。把它移到一個單獨的空段落。 |
| 後端回的不是 JSON（開頭是 HTML） | 後端部署的「誰可以存取」不是「任何人」，請求被導到登入頁了。請工程師在 Apps Script 的部署設定改回「任何人」。 |
| unauthorized／分析金鑰不正確 | `REPORT_ANALYSIS_KEY` 的值不對，或用到了別場演習的金鑰。 |
| 不一致！屬性要求 … 後端實際回 … | `REPORT_TENANT`／`REPORT_EXERCISE` 與金鑰指到的不是同一場。**這一條一定要查清楚再產生**，它擋的就是「封面寫 A 院、分數是 B 院」。 |
| 紀錄表目前沒有可用的評分資料 | 還沒有人送出，或金鑰指到了空的紀錄表。 |
| 報告正在產生中，請稍候，或使用選單的「重設產生狀態」 | 上一輪沒收尾。見 §14.8。 |
| 本環境不支援雷達圖，已改以長條圖呈現相同數值 | **不是錯誤**，是預期中的自動降級，數值完全相同。請把這一行回報。 |
| 本節圖表無法在此環境產生（原因：…），已改以數值表呈現 | 同上，圖變表格，數字不變。請回報括號裡的原因。 |
