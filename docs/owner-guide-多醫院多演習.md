# 多醫院 / 多演習操作手冊（業主用）

> 對象：負責開新演習、發連結、看報告的人。不需要會寫程式。
> 需要工程師的只有兩件事：**第一次貼上新版 Apps Script 程式碼並重新部署**，
> 以及**把註冊表的檔案 ID 填進程式裡那一行**（見 §3 步驟 3）。之後新增醫院、
> 新增演習、換金鑰、結束演習，全部只要改試算表。

---

## 0. 現在（還沒建註冊表時）是什麼狀態

程式裡有一行 `REGISTRY_SPREADSHEET_ID = '';`（空字串）。**空字串 = 整個註冊表機制
關閉**，系統完全照今天的方式運作：

- 評核單連結不帶任何參數 → 讀程式裡寫死的那一份設定試算表、寫進那一份紀錄試算表。
- 分析頁連結不帶任何參數 → 用程式裡那把 `ANALYSIS_KEY`。
- 就算有人在連結後面加了 `?t=xxx`，也**完全沒有作用**（不會報錯、不會換資料）。
  這是刻意的：如果連結已經發出去了而註冊表還沒建好，不能讓演習當天整場掛掉。

> **所以：你可以先把新版程式部署上去，什麼都不做，系統行為一模一樣。**
> 等真的要接第二家醫院或第二場演習時，再照 §3 建註冊表。

---

## 1. 租戶註冊表是什麼

一份新的 Google 試算表，檔名建議叫「**演習評核_租戶註冊表**」，裡面只要一個分頁，
分頁名稱必須是「**租戶註冊表**」。

它的角色是**總機**：一列 = 一場演習，記著「這一場要用哪一份設定檔、哪一份紀錄檔、
哪一把分析金鑰」。系統收到一條帶 `?t=`／`?ex=` 的連結時，就來這裡查該走哪一對檔案。

重點觀念：

| 觀念 | 說明 |
|---|---|
| **一場演習 = 一列 = 自己的兩份試算表** | 設定檔（題庫、代號、評分標準）跟紀錄檔（分數）都各自獨立。這是「去年的 1-1 不會被今年的 1-1 蓋掉」的根本原因。 |
| **代號不是檔案 ID** | `醫院代號`／`演習代號` 只是查表用的鑰匙。程式**永遠不會**拿代號去開檔案，檔案 ID 只能從註冊表這一列讀出來。 |
| **醫院代號要不好猜** | 用 `wanfang-7f3a2c` 而不是 `wanfang`。評核單那支網址沒有任何密碼保護，代號好猜等於別人可以一個一個試出其他醫院的題庫跟代號名冊。 |
| **註冊表只有你看得到** | 評核官手機抓到的資料裡，永遠不會出現任何檔案 ID、任何金鑰、任何註冊表內容。 |
| **改註冊表最多等 2 分鐘生效** | 註冊表有 120 秒快取。要立刻生效見 §7。設定試算表則**完全沒有快取**，改一格、手機重整就生效，跟今天一樣。 |

## 2. 欄位一覽（含目前測試環境的範例列）

欄位順序隨便放，**程式是比對標頭文字，不是比對欄位位置**。欄名可以用括號裡的任一個別名。

| 欄名（別名） | 必填 | 意義 | 範例值 |
|---|:--:|---|---|
| `醫院代號`（`機構代號`） | ✅ | 不可猜的機構 slug，對應連結裡的 `?t=`。只接受**小寫英數字、`-`、`_`，最多 32 字，開頭必須是英數字**。 | `wanfang-7f3a2c` |
| `演習代號`（`場次代號`） | ✅ | 同一家醫院的第幾場，對應連結裡的 `?ex=`。格式同上。**不要用 `2026-01` 這種「數字-數字」寫法**，Google 試算表會自動把它變成日期，程式會直接判這一列無效並告訴你原因。用 `2026a`、`2026b` 最安全。 | `2026a` |
| `顯示名稱`（`名稱`） | | 給人看的標題。會出現在分析頁的網頁標題、頁首大標、CSV 檔名上。留空就自動退回用設定檔裡的「機構名稱」。 | `萬芳醫院急救站 2026 上半年` |
| `設定試算表ID`（`設定檔ID`） | ✅ | 這一場專屬的「演習評核_設定」檔案 ID（網址 `/d/` 和 `/edit` 中間那一長串）。 | `1yiZDnbEFNHddzlTMWaz-bBgI0IvRWXMJ0H3WplyPJDk` |
| `紀錄試算表ID`（`紀錄檔ID`） | ✅ | 這一場專屬的「演習評核_紀錄」檔案 ID。**兩場演習絕對不要共用同一份紀錄檔**（除非照下一欄分成不同分頁）。 | `1jD6DXmPgTV9664XoIveD_cqNQd9V8vq6aM7EtMoI6FM` |
| `紀錄分頁名稱`（`紀錄分頁`） | | 留空 = `評核紀錄`。只有在「兩場演習硬要共用一份紀錄檔」時才填不同值（例如 `評核紀錄_創傷`）。 | `評核紀錄` |
| `分析金鑰`（`金鑰`） | ✅ | 看報告用的密碼，自己產生一串 32 字亂數。**換金鑰 = 改這一格，不用重新部署。** | 見下方 ⚠️ |
| `啟用`（`啟用中`） | | `Y`／留空 = 開放評核。填 `N`／`否`／`停用` = 這場已結束：評核單打不開、送不出，**但報告還看得到**（演習結束後才要做報告）。 | `Y` |
| `開放送出起`（`送出開始`） | | 送出時間窗起點，留空 = 不限。只擋「送出」，**不擋「打開看題目」**（評核官可以提早開表單讀題）。 | `2026/10/06 08:00` |
| `開放送出迄`（`送出結束`） | | 時間窗終點，留空 = 不限。超出範圍時評核單上的送出鈕會變灰並顯示原因，不會先收下分數再丟掉。 | `2026/10/06 18:00` |
| `預設演習`（`預設`） | | 每家醫院**只能有一列**填 `Y`。只給 `?t=` 沒給 `?ex=` 時用這一列。零列或兩列以上都會報錯，系統不會替你猜。 | `Y` |
| `scenePrefix`（`情境前綴`） | | 留空 = `SCENE`。你的最底層項目如果叫「SCENE A1」，編號徽章就會顯示「A1」。改用別的命名（例如「單元 A1」）就把這格填 `單元`。 | `SCENE` |
| `檔案擁有者`（`擁有者`） | | **純備忘，程式完全不讀它。** 記下這對檔案是哪個 Google 帳號擁有的，將來權限出問題時不用猜。 | `charleslin2003@gmail.com` |

> ⚠️ **`分析金鑰` 這一格要填什麼**：第一列（也就是把今天這一場「搬」進註冊表的那一列）
> **必須填現在 `Analysis.html` 裡那把金鑰的原值**，否則今天已經發出去的分析頁連結會
> 立刻失效。那個值在 `Analysis.html` 檔案開頭 `const ANALYSIS_KEY = '…'` 那一行，
> 直接複製貼過來。之後新增的每一列都應該各自產生一把新的亂數。

### 目前測試環境的完整範例列

| 醫院代號 | 演習代號 | 顯示名稱 | 設定試算表ID | 紀錄試算表ID | 紀錄分頁名稱 | 分析金鑰 | 啟用 | 開放送出起 | 開放送出迄 | 預設演習 | scenePrefix | 檔案擁有者 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `wanfang-7f3a2c` | `2026a` | 萬芳醫院急救站 2026 上半年 | `1yiZDnbEFNHddzlTMWaz-bBgI0IvRWXMJ0H3WplyPJDk` | `1jD6DXmPgTV9664XoIveD_cqNQd9V8vq6aM7EtMoI6FM` | `評核紀錄` | （照抄 `Analysis.html` 裡 `ANALYSIS_KEY` 的值） | `Y` | （留空） | （留空） | `Y` | `SCENE` | charleslin2003@gmail.com |

舊連結不會失效。發布任何新連結之前，請用 §8 的自我檢測把兩條路都跑一次確認。

## 3. 第一次建立註冊表（只做一次）

1. 新開一份 Google 試算表，檔名「演習評核_租戶註冊表」。
2. 把唯一那個分頁改名成「**租戶註冊表**」，第一列照 §2 打上欄名（至少五個必填欄）。
3. 複製網址裡的檔案 ID，**請工程師**把它填進 `apps-script/ConfigWithSubmit.gs` 的
   `REGISTRY_SPREADSHEET_ID = '';` 那一行，然後重新部署（部署步驟見 §13）。
4. 照 §2 的範例列填**第一列**（指向現有的那兩份試算表）。
5. 跑一次自我檢測（§8），確認「✅ 設定檔可讀、✅ 紀錄檔可寫」。
6. 這一步做完之後，**以後都不用再動程式**。

## 4. 新增一家醫院

1. **複製兩個範本檔**：在雲端硬碟對現有的「演習評核_設定」和「演習評核_紀錄」各按
   「檔案 → 建立副本」，改名成那家醫院的版本（例如「演習評核_設定_○○醫院_2026上」）。
2. **把紀錄檔的舊資料列刪掉**（只留標頭列）。設定檔的題庫則照那家醫院的架構改。
3. **確認權限**：執行 Web App 的那個 Google 帳號，必須對設定檔有「**檢視者**」、
   對紀錄檔有「**編輯者**」。少了編輯權，評核官按送出會失敗。
4. **註冊表加一列**：
   - `醫院代號`：自己想一個不好猜的，例如 `地名縮寫-6碼亂數`（`taoyuan-91c4de`）。
     **不要用 `taoyuan` 這種一猜就中的字。**
   - `演習代號`：`2026a`。
   - `設定試算表ID` / `紀錄試算表ID`：貼上步驟 1 那兩個檔案的 ID。
   - `分析金鑰`：產生一把**新的** 32 字亂數（不要跟別家共用，程式會直接擋）。
   - `啟用` = `Y`，`預設演習` = `Y`。
5. **跑自我檢測**（§8），確認兩個 ✅。
6. **發兩條連結**（§10）。

## 5. 同一家醫院新增第二場演習

跟 §4 幾乎一樣，差別只有三點：

- `醫院代號` **沿用**同一個（這樣「過去演習」清單才看得到同一家的歷史場次）。
- `演習代號` 換新（`2026b`）。
- `分析金鑰` 可以跟同院前一場**共用同一把**（一家醫院一把儀表板金鑰），也可以各場
  一把。**但絕對不能跟別家醫院共用** —— 同一把金鑰出現在兩個不同 `醫院代號` 底下時，
  那些列會全部被判無效，因為那等於 A 院改一下網址就能看 B 院的報告。

**還有一件事**：把舊那一場的 `預設演習` 清空，只留新場次那一列是 `Y`
（兩列都是 `Y` 會讓只帶 `?t=` 的連結直接報錯，系統不會替你猜）。

> **替代做法（兩場共用一份紀錄檔）**：如果真的不想多開檔案，可以兩列填同一個
> `紀錄試算表ID`，但 `紀錄分頁名稱` 必須不同（`評核紀錄_創傷` / `評核紀錄_大量傷患`），
> 而且那個分頁要先在檔案裡建好、標頭列照抄。**（紀錄試算表ID + 分頁名稱）重複的列
> 會被全部判無效** —— 這是故意的硬擋：那正是「複製了一列但忘記換紀錄檔」害兩場演習
> 互相覆蓋分數的唯一入口。

## 6. 結束一場演習

把那一列的 `啟用` 改成 `N`，**就這樣**。

| 改成 N 之後 | 結果 |
|---|---|
| 評核官打開評核單 | 看到「這場演習已結束，不再開放評核。」 |
| 評核官按送出 | 被拒絕，同一句話 |
| 你打開分析頁 | **照常可以看**（報告本來就是演習結束後才做） |
| 「過去演習」清單 | 列出來、標示為「已結束」 |
| 註冊表的重複檢查 | 這一列不再參與（所以明年複製一列重辦時不會跟它打架） |

另一種做法是用 `開放送出起`／`開放送出迄` 預先設好時間窗，演習當天時間一到自動開、
時間一過自動關，不用人手改。兩者可以同時用。

## 7. 換分析金鑰（不用重新部署）

1. 在註冊表找到那一列，把 `分析金鑰` 改成新的一串亂數。
2. 跑一次 `action=flush`（下一段）讓它立刻生效，或等 2 分鐘。
3. 把新的分析頁連結（`…?t=…&ex=…&key=新金鑰`）重新發給該看的人。舊連結立刻失效。

**立刻生效（清掉註冊表快取）**：在瀏覽器網址列打

```
<RECORD_URL>?action=flush&adminKey=<你的管理金鑰>
```

回 `{"ok":true,"flushed":["reg:v2"]}` 就是清好了。這個動作**只**清註冊表快取，
不會碰送出去重的那份快取（碰了會讓正在重試的送出變成重複列）。

> **管理金鑰（ADMIN_KEY）**是另一把金鑰，只給 `action=selftest` 和 `action=flush` 用。
> 它**不寫在任何上架的網頁檔案裡**，只能由你自己打在網址列。程式裡預設是空字串 =
> **這兩個功能停用**；要用的話請工程師在 `ConfigWithSubmit.gs` 的 `ADMIN_KEY = '';`
> 填一串亂數並重新部署。**不要跟 `分析金鑰` 用同一串。**

## 8. 自我檢測 `action=selftest`：怎麼跑、答案怎麼讀

新增完一場演習（或任何時候懷疑權限有問題）就跑它。在瀏覽器網址列打：

```
<RECORD_URL>?action=selftest&adminKey=<管理金鑰>&t=<醫院代號>&ex=<演習代號>
```

（`t`／`ex` 可以省略，省略就是檢查「不帶參數時會用到的那一組」。**新增完一場演習後，
建議兩條路都各跑一次**：帶參數的那條和不帶參數的那條。）

回來的是一段 JSON。先看 `messages` 那一串中文，那是給人看的：

| 看到的訊息 | 意思 / 該做什麼 |
|---|---|
| `✅ 設定檔可讀：<檔名>` | 設定試算表打得開，而且檔名就是你以為的那一份。**檔名不對 = 註冊表那一列的 ID 貼錯了。** |
| `✅ 紀錄檔可寫` | 真的對紀錄檔做過一次無害的寫入測試（寫一個隱藏標記再刪掉，**不會新增任何一列、不會動任何一格**）。 |
| `⚠️ 紀錄檔無法寫入：…` | 權限不足。到紀錄檔按「共用」，把執行 Web App 的那個帳號加成「編輯者」。 |
| `⚠️ 設定檔缺少分頁：…` | 那幾個分頁名稱打錯或被刪了（需要：演習資訊／人員代號／評分標準／項目與問題／對應指標）。 |
| `⚠️ 註冊表第 N 列無效：<原因>` | 第 N 列被判無效，**整列失效**，走到那一列的連結會收到「註冊資料有問題」。原因就寫在後面，照字面修。 |
| `⚠️ 註冊表無法使用，已退回程式內建的那一組試算表：…` | 註冊表打不開／分頁名稱不對／一列資料都沒有。這時系統**不會掛**，會退回用程式裡寫死的那一組，但所有 `?t=` 都失去作用。 |
| `尚未設定租戶註冊表…` | 正常，代表還在 §0 的狀態。 |
| `尚未設定管理金鑰（ADMIN_KEY），自我檢測未啟用。` | 見 §7 最後那段，請工程師填 `ADMIN_KEY` 並重新部署。 |

其他欄位快速對照：

- `tenantSource`：`registry` = 這條連結真的從註冊表查到了一列；`fallback` = 用的是程式
  內建那一組。**新增完一場演習後，帶參數那條一定要是 `registry`。**
- `config.codeCount` / `criteriaCount` / `leafCount` / `questionCount`：代號幾個、評分
  標準幾級、最底層項目幾個、題目幾題。**數字跟你的試算表對不起來就是欄名打錯了。**
- `record.headerColumns`：紀錄表第一列實際讀到的欄名。想確認「觀察紀錄」那一欄有沒有
  被認出來，就看它在不在 `presentOptional` 裡。
- `record.missingRequired`：紀錄表缺了必要欄（問題ID／分數／人員代號／送出時間）。
  有東西 = 送出一定會失敗。

> **自我檢測的回傳內容刻意只有「檔名、分頁名、欄名、數量」**，不含任何試算表 ID、
> 任何金鑰、任何人員代號、任何題號、任何分數。所以它可以安心截圖給別人看。

## 9. 為什麼某一列會被判「無效」

程式每次讀註冊表都會跑五條檢查。**被判無效的列等於不存在**：走到它的連結會收到
「這場演習的註冊資料有問題，請聯絡系統管理者。」，**絕對不會改讀別一列的資料**，
也不會偷偷退回程式內建那一組。具體原因只出現在 `action=selftest`。

| # | 規則 | 為什麼要這麼嚴 |
|---|---|---|
| 1 | `醫院代號`+`演習代號` 重複 → **那一組全部無效**（不是「第一列獲勝」） | 否則「哪一列說了算」要看誰排在上面，同一條連結今天明天看到不同資料 |
| 2 | `紀錄試算表ID`+`紀錄分頁名稱` 重複 → **那一組全部無效** | 兩場演習寫進同一張表，同樣的題號會互相覆蓋分數 —— 這是整個系統最嚴重的那個老問題，必須硬擋 |
| 3 | 同一把 `分析金鑰` 出現在**不同** `醫院代號` 底下 → 共用那把金鑰的列全部無效 | 否則 A 院只要改一下網址的 `?t=` 就能看 B 院的報告。**同一家醫院的不同場次共用一把金鑰是允許的** |
| 4 | 任一必填欄空白 → 只有那一列無效 | — |
| 5 | 代號格式不合、檔案 ID 格式不合、時間格式讀不懂 → 只有那一列無效 | 格式不合的代號如果被當成檔案 ID 用，整個系統就變成「任意檔案讀取代理」 |

規則 1、2 **只比對 `啟用=Y` 的列**（所以封存的舊列不會跟新列打架）；規則 3 **比對全部
列**（封存了，那把金鑰還是能看報告，仍然是有效憑證）。

常見原因對照：

- `演習代號 被試算表判讀成日期，請把該格設成純文字格式` → 你填了 `2026-01`。
  把那一格「格式 → 數值 → 純文字」再重打，或直接改成 `2026a`。
- `醫院代號 格式不合（只允許小寫英數、- 與 _，最多 32 字）` → 有大寫、中文或空格。
- `紀錄試算表ID+分頁名稱 與第 N 列重複，兩場演習會互相覆蓋分數` → 複製列時忘了換紀錄檔。

## 10. 連結怎麼發

| 給誰 | 連結長相 |
|---|---|
| 評核官（評核單） | `…/Start.dc.html?t=<醫院代號>&ex=<演習代號>` |
| 評核官（該院只有一場、且那列 `預設演習=Y`） | `…/Start.dc.html?t=<醫院代號>` |
| 你自己（分析儀表板） | `…/Analysis.html?t=<醫院代號>&ex=<演習代號>&key=<分析金鑰>` |
| 你自己（直接開列印報告） | 上面那條再加 `&view=report` |

- **評核官那條連結裡永遠不會有任何金鑰**，也不該有。
- **分析頁那條連結等於密碼**，只給該看的人，不要貼進群組。
- 按下分析頁的「產生報告」之後，網址列的 `?key=` 會被自動清掉（這樣用瀏覽器列印時
  頁尾印出來的網址不會把金鑰印在紙上）。代價是**那之後按重新整理就要重新貼一次連結**。

## 11. ⛔ 鐵則：演習開始到報告歸檔之間，不要編輯設定試算表

**從第一位評核官打開連結，到那一場的報告做完歸檔為止，請不要動「演習評核_設定」
這份檔案的任何一格。** 下一場的題庫請改在**新複製出來的那一份**上。

兩個具體後果：

1. **飛行中的送出會失敗、分數會不見。** 送出時程式會拿「**當下**」的設定表來驗證：
   人員代號在不在名單裡、項目名稱找不找得到、題號對不對得上。評核官手機在收訊不好
   的地方會自動重試三次 —— 如果你剛好在這幾秒之間改了項目名稱或題號，那次重試會被
   以「未知的項目名稱」「未知的問題ID」拒絕，而他已經填好的那一頁分數就沒了。
   （對應程式：`ConfigWithSubmit.gs:740-760` 的白名單比對。）
2. **已經發出去的報告標籤會被回頭改寫。** 分析頁上的「情境階段／測試情境／評核潛能／
   4S 元素／指標」這些標籤，**不是送出當時存起來的，是看報告的那一刻才去設定表對照
   出來的**。你為了下一場把題庫換掉，上一場那份已經印出來的報告再打開一次，標籤就跟
   紙本對不上了，而且沒有任何警告。（對應程式：`ConfigWithSubmit.gs:945-1045` 讀取時
   的對照邏輯。）

> **解法正是本手冊在講的事**：下一場 = 複製兩份新檔案 + 註冊表加一列。
> 這樣「準備下一場」從此不再需要碰上一場的任何檔案。

另外，紀錄試算表如果補上了「測試情境／評核潛能／4S 元素／評核題目／指標代號」這幾個
選填欄（見 `README.md`），送出當時就會把標籤寫死在那一列，後果 2 就會自動消失。
報告的「資料品質」章節會明白印出「本報告標籤取自送出當時快照 N 題／讀取時對照 M 題」，
讓看報告的人知道自己看的是哪一種。

## 12. 其他會動到分數的操作，請在兩場演習之間做

| 操作 | 風險 |
|---|---|
| 改「演習資訊」的演習名稱 | 不帶 `?t=`／`?ex=` 的舊連結，評核官手機上的「已完成」記錄是用演習名稱當鑰匙存的 —— 改名的瞬間全部評核官的進度都會歸零，END 畫面也會變成到不了。**帶 `?t=&ex=` 的新連結沒有這個問題**（它改用代號當鑰匙）。 |
| 重新部署 Apps Script | 這是唯一一個能同時打壞設定載入和送出的步驟。演習進行中絕對不要做。 |
| 在紀錄表插欄 | 程式是比對標頭文字、不看欄位位置，所以插欄對程式安全；但你自己疊在上面的圖表、篩選檢視、具名範圍、公式輔助欄可能會跑掉。插欄前先複製一份當回滾點。 |
| 刪紀錄表的列 | 沒有任何還原機制，分析頁就是直接讀整張表。 |

## 13. 重新部署步驟（需要工程師，只在改程式碼時做）

1. Apps Script 編輯器 → 貼上新版 `ConfigWithSubmit.gs`。
2. **部署 → 管理部署作業 → 編輯（鉛筆）現有那一個部署**
   → 版本選「**新版本**」→ 部署。
3. ⚠️ **不要選「新增部署作業」** —— 那會產生一條**不同**的 `/exec` 網址，
   舊網址還活著但不會更新，症狀是「程式明明改了卻完全沒生效」。
4. 確認「執行身分 = 我」「誰可以存取 = 任何人」。執行身分設錯會讓每支評核官手機
   被要求登入 Google。
5. 部署後**先用手機實際跑一次完整送出**，再公布連結。
6. 要回滾就在同一個對話框把版本切回上一版。
