## 1. ⚠️ 先看這個：沙箱與正式站共用同一把分析金鑰

你當初交代的原則是「我用之前在我雲端資料做測試，不要跟正式混用」。**試算表與
`/exec` 確實是分開的，但金鑰沒有分開。**

```
dev    Analysis.html  ANALYSIS_KEY = WrHSeT…8Jub  (32 字)
master Analysis.html  ANALYSIS_KEY = WrHSeT…8Jub  (32 字)   ← 逐字相同
```

而且這個 repo 是 public 的，正式站今天實測仍然公開供應
`/apps-script/ConfigWithSubmit.gs` 與 `/CLAUDE.md`（都回 **200**）。
金鑰在 `ConfigWithSubmit.gs:49`；`CLAUDE.md` 裡**只有變數名、沒有金鑰本身**
（它洩漏的是架構與弱點，不是憑證）。

**精確講清楚是什麼問題、不是什麼問題**，因為這一條很容易被反向誤讀：

- ❌ **不是**「改一邊會打壞另一邊」。兩邊在金鑰這一層**完全隔離**：沙箱帶 `?t=` 的
  `action=analysis` 比對的是**註冊表那一列**的 `分析金鑰`
  （`ConfigWithSubmit.gs:708`），正式站那支指令碼根本沒有註冊表程式碼，比對的是它
  自己專案裡的 `ANALYSIS_KEY` 常數。兩個不同的 Apps Script 專案、兩個不同的 git
  分支，沒有任何共用儲存。
- ✅ **真正的問題是「目前剛好是同一個字串」**：所以 public repo 的洩漏會波及正式站，
  而且輪替要分別動兩邊、不會自動同步。
- ✅ 而且**沙箱這半邊現在就可以單獨換，正式站毫無影響**——註冊表 `2026b` 那一列用的
  已經是另一把金鑰了（`UE8QYl…`），這本身就證明金鑰是逐列的。

`Analysis.html` 本來就**設計成**把金鑰內嵌在頁面裡，儀表板的門禁一直是「沒公開的
網址＋那把金鑰」，所以「金鑰是公開的」不是新問題。**新的只是「兩邊同一把」。**
這讓 `docs/multi-tenant-and-report-plan.md` §6.6 的「換金鑰」從長期待辦變成應該排前面
的事，而且第一步很便宜：**改註冊表 `2026a` 那一列的 `分析金鑰`、再改 `dev` 的
`Analysis.html` 一個常數就好**，正式站不會被動到。

> ⚠️ **連帶一個現在就會踩到的事：`Analysis.html` 的場次下拉選第二場會報錯。**
> 它送的是 `KEY = Q.get('key') || ANALYSIS_KEY`，而 `action=analysis` 比對解析出來那一
> 列的金鑰。`2026a` 的金鑰等於內嵌的那把，`2026b` 是另一把，所以下拉選「萬芳醫院
> 急救站」會直接拿到 `{"error":"unauthorized"}`。
> 下拉本身列得出兩場（`action=exercises` 只要金鑰符合該院任一有效列就授權），
> **清單載得到、個別場次卻讀不到**——這個不對稱會讓症狀看起來像後端壞了。
> 要看 `2026b` 得在網址加 `?key=UE8QYl…`。

1. **合併後 `master` 沒有任何自動化回歸。** `scripts/smoke.sh` 的
   `guard_production` 會對正式 `/exec` 前綴直接 `exit 2`，所以那支腳本永遠不會對
   `master` 的端點跑。
2. **兩支容器綁定腳本在正式環境還需要各自的指令碼屬性**（不是 repo 常數）：
   `Setup.gs` 需 `SETUP_SITE_BASE`（必填，目前範例指向測試站）與
   `SETUP_CONFIG_TEMPLATE`（選填）；`Report.gs` 需 `REPORT_ANALYSIS_KEY`／
   `REPORT_API_URL`／`REPORT_TEMPLATE_DOC_ID` 三個必填。

## 6. 會浪費你時間的坑

這些都是這幾天真的踩過的：

| 坑 | 症狀 | 真正原因 |
|---|---|---|
| 貼錯 Apps Script 專案 | `Cannot call SpreadsheetApp.getUi()` | 從 Apps Script 首頁新建的是**獨立專案**。一定要從該試算表「擴充功能 → Apps Script」進去 |
| 在編輯器按「執行」開對話框 | 執行記錄一直轉到逾時 | 對話框只能從試算表選單點。編輯器沒有試算表 UI 可以顯示 |
| 跑 `onOpen` 想拿授權 | 跑完了但權限還是不足 | 加選單不需要 `script.container.ui`。要跑**會開對話框的函式**才會觸發授權 |
| 改註冊表後沒反應 | 看起來沒生效 | 有 **120 秒**快取，且 `flush` 需要 `ADMIN_KEY`（現在是空的） |
| 重複用同一個演習代號測試 | 新場次一開場就顯示已完成 | `localStorage` key 是 `醫院/場次:代號`，**沒有隨機成分**。每輪換新代號 |
| 新建的紀錄分頁找不到 | 分頁列上看不到 | `insertSheet` 插在**目前作用中分頁後面**，不是最後。按 F5 並左右捲 |
| 推送後測試站沒更新 | 還是舊版 | Vercel 建置要時間，而且**不是固定值**（看當時的佇列）。2026-10-12 那次大約三分鐘才拿到新版。**不要太早判它沒建置**，但也不要把「三分鐘」當門檻用——要確認就比 sha256：`git show dev:Analysis.html \| sha256sum` 對上 `curl …/Analysis.html \| sha256sum` |
| 照試算表字面寫潛能比對 | 三項潛能整批消失 | 試算表仍寫「回應」，程式比的是「反應」。中間有 `normPotential_` 與 `normalisePotentials` 兩層折疊 |
| 用第 3 節的 curl 去驗 `Config.gs` | 看不出差別 | 那個 curl 打的是 `RECORD_URL`。`Config.gs` 是另一個部署，不服務 `action=analysis` |

## 7. 工作習慣

- **一律在 `dev` 做**，`master` 凍結
- commit 可以直接做，**push 前要先問**
- **新增任何後端程式、內部文件或暫存檔，要擋兩層，不是一層：**
  - `.vercelignore` 管「網站會不會提供這個檔案」
  - **根目錄 `.gitignore` 管「會不會進到公開的 git 歷史」**

  repo 是 public 的，所以 git 本身就是對外介面。`.vercelignore` 先前自稱是
  「公開／非公開的唯一分界」，**那句話是錯的**，2026-10-12 已更正
  （commit `19145c9`）。兩層的補救難度也不對等：Vercel 設定改一下就生效，
  **git 歷史裡的東西清不乾淨**。
- 寫錯誤訊息與提示時，**提不出證據就不要指方向**。這幾天有三個錯誤提示各自把人
  送去檢查唯一沒壞的那個東西（說 `ReportDialog` 檔案不見、說「是獨立專案」、
  說去跑 `onOpen` 拿授權）。**給錯提示比不給提示更糟**；原因無法從訊息證明時，
  就把候選原因全列出來。
