# 人工測試檢查表

這份清單只放**真的沒辦法自動化**的檢查。能自動化的都已經在 `scripts/smoke.sh` 裡了，
不要把東西重複寫到這裡來 —— 一份會自動跑的測試，價值遠高於一份要人記得跑的清單。

## 先搞清楚哪些不用人工做

```
bash scripts/smoke.sh                  # 18 項裡的 15 項，唯讀，可無限重跑
bash scripts/smoke.sh --with-write     # 加上寫入隔離與冪等
```

涵蓋：場次清單與排序、預設演習唯一性、無金鑰分支的機密欄位紅線、未知代號硬錯誤、
跨醫院隔離、fallback 相容、兩道送出閘門、跨租戶金鑰隔離、寫入隔離、冪等。

**每次重新部署 Apps Script 之後請先跑它。** 退出碼 0 才往下做人工項目。

金鑰走環境變數，不寫在檔案裡：

```
export EVAL_KEY_MAIN=<醫院預設場次的分析金鑰>
export EVAL_KEY_CLINIC=<分院的分析金鑰>
```

---

## 為什麼下面這些只能人工

| 類別 | 卡在哪 |
|---|---|
| Apps Script 執行 | `SpreadsheetApp` / `DriveApp` / `DocumentApp` 只存在於 Google 的執行環境。沒有任何外部工具能驅動它們 —— 連雲端 agent 也不行，這不是權限問題而是執行環境問題 |
| 瀏覽器渲染 | QR 碼掃不掃得到、列印版面有沒有被切、手機上字會不會擠，都需要真的螢幕與真的相機 |

## M1. 精靈：複製一份新的設定檔 ⬜

**還沒有人走過這條路。** 目前建的兩場都是「沿用現有的」，所以共用同一份演習資訊與題目。
這條路是「每場演習有自己的時間、地點、題目」的唯一實現方式。

**前置**：指令碼屬性 `SETUP_CONFIG_TEMPLATE` 要有值。

**步驟**：租戶註冊表 → `演習場次管理` → `新增一場演習…`

- 醫院：既有的那一家
- 演習代號：`test01`（用完就刪）
- 開放送出起／迄：今天 → 明天
- 設定檔：**複製一份新的設定檔**
- 演習日期／地點／說明：隨便填，等下要驗證
- **「設為預設」不要勾** —— 勾了會把現有預設搶走（精靈會自動取消舊的，這是正確行為，
  但會讓你多一步復原）

**預期**：

1. 雲端硬碟多一個「test01 顯示名稱｜設定」檔案
2. 紀錄檔多一個 `評核紀錄_test01` 分頁，表頭 7 欄，**而且是從既有分頁抄的**
   （所以 `觀察紀錄` 那一欄要在）
3. 註冊表多一列
4. 畫面出現兩張 QR 與三條網址

**驗收**：

- 打開複製出來的設定檔 →「演習資訊」分頁應該有 `演習名稱`、`演習日期`、`說明`
  （地點併在說明裡）
- 開 `?t=<醫院>&ex=test01` → **抬頭顯示新的演習名稱**，不是舊那份設定檔的主題。
  這一點就是整條路存在的理由：抬頭來自設定檔，不是註冊表的顯示名稱

**清乾淨**：刪註冊表那一列、刪 `評核紀錄_test01` 分頁、刪掉複製出來的檔案。
刪完跑一次 `scripts/smoke.sh` 確認沒有留下壞掉的狀態。

**失敗時**：把對話框的紅色訊息整段貼出來。精靈的設計是「所有檢查都在任何寫入之前跑完」，
所以失敗時原則上什麼都沒寫；若訊息顯示它已經建了檔案才失敗，那是個 bug，要回報。

## M2. 精靈：自動取消舊的預設演習 ⬜

2026-10-08 的 bug 修正，**修完之後還沒有人實際觸發過**。

**步驟**：建一場新場次，這次**勾選**「設為預設」。

**預期**：

- 結果畫面的說明裡出現一行「原本的預設演習「…」已取消預設」
- 跑 `scripts/smoke.sh` → `預設演習恰好一個` 仍然 PASS

**為什麼重要**：沒有這段，`?t=` 不帶 `?ex=` 的連結（評核官掃的那張醫院通用 QR）
會整家醫院回 `AMBIGUOUS_DEFAULT`，而註冊表看起來完全正常。
`scripts/smoke.sh` 會抓到這個狀態，但抓到時已經壞了 —— 這一項是確認它根本不會發生。

## M3. Report.gs 全流程 ⬜

**整個專案最後一塊從未被驗證的程式碼。** 它的圖表全部是「能畫就畫、畫不出來退成表格、
再不行印一句話」，而 `Charts` API 的行為沒有任何人從外部確認過。

**前置**：三個指令碼屬性 —— `REPORT_ANALYSIS_KEY`、`REPORT_API_URL`、
`REPORT_TEMPLATE_DOC_ID`（最後一個是範本文件，必填，沒有它會直接拒跑）。

**步驟**：演習評核_設定 試算表 → `演習評核報告` → 先按 `檢查設定（不產生報告）`，
過了再按 `產生評核報告…`。

**要回報的，依重要性排序**：

1. **對話框裡的「警告／降級紀錄」全文。** 這是最有價值的部分 —— 每一次圖表降級
   都會記在那裡，而那正是外部完全無法預測的部分
2. 有沒有產出 Google 文件？連結打得開嗎？
3. 文件裡的圖表是**原生圖表**、**退成表格**、還是**只有一句話**？
4. 有沒有跑完？還是中途停在「（部分完成）」？
5. 失敗的話，紅字整段

**已知的脆弱點**（回報時可以順便看一下）：

- 範本裡的 `{{SEC_*}}` 錨點必須是**頂層的單獨段落**。放在表格儲存格、頁首頁尾或
  項目清單裡，內容會被插到錯誤的位置 —— 程式會具名擋下來，但值得確認訊息看得懂
- 六個必要章節缺一個就整份拒跑
- 統計數字一律取自 `action=analysis`，**不重算**。如果文件上的數字跟分析平台對不起來，
  那是 bug，不是四捨五入

## M4. 評核官的實機流程 ⬜

要**真的用手機**，不是桌機縮小視窗。

1. 用手機相機掃「醫院通用 QR」→ 應該進到場次清單
2. 清單上**只有今天那一場可以點**。已結束的場次是灰的、點不下去，而且預設收在
   「顯示已結束場次（N）」後面
3. 選一場 → 選評核官代號 → 選項目 → 評分 → 送出
4. 回到項目清單，**剛才那項應該變灰並加上（已完成）**
5. 按「更換場次」→ 回到清單，再進來「已完成」標記還在
6. 把全部項目做完 → 應該跳到 END 畫面

**常見陷阱**：如果清單上每一場都顯示「開放中」，代表那些列的 `開放送出起／迄` 是空的。
空白等於永遠開放，評核官會挑錯場次而且真的送得出去。

## M5. 列印 ⬜

1. **QR 碼**：用精靈的「列印 QR 碼」印出來，**用別人的手機掃**。印在紙上還掃得到才算過
2. **分析平台報告**：`Analysis.html` → 產生報告 → Ctrl+P

   ⚠️ Chrome 的「**背景圖形**」必須打勾，否則 3D 柱狀圖和 4S 色譜會印成全白。
   QR 碼不受影響（它是 SVG path，屬於內容不是背景），但圖表會
3. 確認表格沒有被切掉、圖表沒有擠成一團

## 回報格式

做完把這份清單的勾選狀態、加上 M3 的警告紀錄全文貼回來即可。
失敗的項目請附**完整**錯誤訊息，不要摘要 —— Apps Script 的錯誤訊息常常
最後一句才是真正的原因。
