# 演習評核流程 — design reference

This is a design mockup created in a visual design tool (an appifact
design canvas), exported as a standalone page. Treat it as a REFERENCE
MOCKUP, not production code: the markup and inline styles carry the
design's precise values — colors, font sizes, spacing, radii, shadows,
layout — which an implementation should replicate faithfully in its own
components and styling system rather than copy wholesale.

## Contents

- `Start.dc.html` — the artboard (a Design Component: an `<x-dc>`
  template + a small logic class). The values to replicate live in its
  inline `style="…"` attributes and the `<helmet><style>` block.
- `support.js`, `vendor/react*.js` — the runtime that renders the
  component in a browser; not part of the design.

## Viewing

Serve the folder (e.g. `python3 -m http.server`) and open `Start.dc.html`;
some browsers block the scripts over file://.

## ⚠️ 2026-10-12 的兩個改名（你的表**不用改**也能繼續用）

業主在 2026-10-12 把兩個用語改掉了。兩個都是**新名字優先、舊名字繼續接受**，
所以**現有的試算表什麼都不用動**，畫面與報告會直接換成新說法：

| 舊 | 新 | 影響到哪 |
|---|---|---|
| 情境 | **場景** | 欄位名 `情境階段` → `場景階段`、`測試情境` → `測試場景與目標`；畫面上的「情境編號對照表」→「場景編號對照表」 |
| 回應 | **反應** | 「對應指標」的 `評核潛能` 欄裡那個值 |

下面的說明一律寫**新名字**，舊名字會註明「仍可用」。兩件要知道的事：

1. **欄位名用的是「別名比對」**：`場景階段` 與 `情境階段` 兩個寫法程式都認得，
   所以你要不要把表頭改成新名字，純粹看你自己想不想統一，不改不會壞。
2. **`評核潛能` 欄裡的 `回應` 也一樣不用改。** 程式會自動把它當成 `反應`。
   你現在這張表裡填的就還是 `回應`，而畫面與報告上顯示的已經是「反應」——
   這是正常的，不是對不上。

## 設定試算表填寫說明（演習資訊）

「演習評核_設定」試算表的「演習資訊」工作表是 key/value 列（A 欄標籤、B 欄
值），沒有固定標頭列，逐列掃描比對：

| A 欄（標籤） | 讀到哪個欄位 | 用途 |
|---|---|---|
| 機構名稱 | `orgName` | `Analysis.html` 頁首大標題（「萬芳醫院｜演習評核分析平台」的機構名部分） |
| 演習名稱 | `exerciseName` | 內部識別用，`Start.dc.html` 選擇畫面的標題，沒填時改用主題/演習類別/機構名稱當備用 |
| 演習主題 或 主題 | `exerciseTopic` | `Analysis.html`「主題」KPI 卡 |
| 演習類別 | `exerciseCategory` | `Analysis.html` 頁首徽章。**跟「主題」是兩個不同欄位**，不要共用同一列——試算表上同時存在「主題」（較長的描述，例如「社區急救站實兵演練」）跟「演習類別」（較短的分類，例如「實兵演練」）兩列，分別對應上面兩個不同欄位 |
| 演習日期 | `exerciseDate` | 頁首徽章；儲存格是日期型別也會自動格式化成 `yyyy/MM/dd`，不會變成一長串英文日期字串 |
| 說明 | `exerciseDesc` | `Analysis.html`「說明」KPI 卡 |
| 啟用觀察紀錄 | `commentEnabled` | 控制問卷每一題下方的「觀察紀錄」文字框要不要出現。只有明確填 `N`／`n`／`否`／`關閉`／`FALSE`／`False`／`false` 才會關掉，**空白或沒有這一列都當作開啟**。⚠️ B 欄如果放的是**核取方塊**，沒打勾讀出來就是 `false`——等於**整場關掉觀察紀錄**；要用核取方塊就記得打勾（少一個留言框，比意外關掉報告唯一的質性資料來源好修） |
| 低分需說明門檻 | `commentRequiredBelow` | 填 `2` 的意思是「評 1 或 2 分的題目一定要寫觀察紀錄才能送出」。空白、非數字、或沒有這一列都當 `0`（永不強制）。這個限制只擋在手機端的送出按鈕上，後端不會因為沒寫說明就拒收分數 |

這八列都是選填，沒填就是空字串（最後兩列沒填則是「留言框開著、不強制說明」），
前端會顯示 `—` 或整個不顯示該區塊（視欄位而定）。改這張表不用重新部署 Apps
Script，跟下面「項目與問題」一樣即時生效。

## 設定試算表填寫說明（項目與問題）

畫面上「選擇評核項目」要出現什麼、分幾層選，全部由 `演習評核_設定` 試算表裡
的「項目與問題」工作表決定，不用改程式。這個表有兩種填法：

### 單層（最簡單的填法，適合只有一組 SCENE 項目的場合）

標頭用 `項目名稱`、`問題ID`、`問題內容` 三欄，同一個項目名稱重複幾列就是幾個
問題：

| 項目名稱 | 問題ID | 問題內容 |
|---|---|---|
| SCENE 範例一 | Q1 | 問題內容一 |
| SCENE 範例一 | Q2 | 問題內容二 |
| SCENE 範例二 | Q1 | 問題內容一 |

使用者畫面上會直接看到「範例一」「範例二」兩個按鈕（畫面會自動去掉 `SCENE `
前綴），點下去就直接進評分標準／問卷，沒有中間分層。

### 多層（階段→場景兩層；**萬芳 10/3 這一場用的就是這種**）

> 實測 2026-10-12：10/3 那張表的「項目與問題」表頭是
> `情境階段`／`演練單元`／`測試情境`／`評核題號`／`評核題目`，也就是**兩層**
> （層1＝情境階段、層2＝演練單元）。如果你是來照範例對自己的表，對的是下面這一節，
> 不是上面那一節。

把 `項目名稱` 換成 `層1`、`層2`（N 從 1 開始連續編號），最後一欄一樣接 `問題ID`、`問題內容`：

| 層1 | 層2 | 問題ID | 問題內容 |
|---|---|---|---|
| 階段一 | 場景甲 | Q1 | 問題內容一 |
| 階段一 | 場景甲 | Q2 | 問題內容二 |
| 階段一 | 場景乙 | Q1 | 問題內容一 |
| 階段二 | 場景丙 | Q1 | 問題內容一 |

使用者畫面上會先看到「階段一」「階段二」兩個按鈕（層1），點進去才看到該階段
底下的場景（層2），點到場景才真正進評分標準／問卷。

`層1` 這一欄的標頭也可以直接寫 `場景階段`（或舊名 `情境階段`），`層2` 可以寫
`演練單元`——程式比對的是文字別名，不是欄位位置。

⚠️ **手機畫面最多兩層。** 後端讀得懂任意多欄「層N」，但手機上的選擇畫面同一時間
只能展開一個分組：加了 `層3`（例如 階段→場景→子場景）之後，點開第二層會把第一層
收起來，**最底層的項目會點不到**。要分三層以上得先改 `Start.dc.html`。

### 填寫時的注意事項

- 同一列裡，`層1`、`層2`… 由左到右不能中間空白後又填值（例如層1有值、層2留
  空、卻在下一列又對同一個層1值填了層2）——空白的那一層當作「到這裡就是最底
  層」，之後的問題會被歸到那一層底下。
- 每個「層N」欄位裡的名稱，同一層之間可以重複出現在不同分組下（例如兩個階段
  底下都各有一個叫「場景1」的項目），但**同一個分組底下不要有重複的名稱**，
  否則會被視為同一個項目、問題會合併在一起。
- ⚠️ 補充一個目前仍存在的限制（缺陷 D4）：手機端記「這個項目我填完了」是用
  **最底層項目的名稱**當鍵值，所以**整張表裡只要有兩個最底層項目同名**（即使在
  不同分組底下），它們會共用同一個「已完成」標記——填完一個，另一個也會變灰。
  要避開就讓最底層名稱全表唯一（例如都帶上編號）。
- 改這張表不需要重新部署 Apps Script，`doGet` 每次都會重新讀取試算表最新內
  容；但如果連 `.gs` 程式檔本身也改了，才需要照 `CLAUDE.md` 裡的步驟重新部署。

### 選填欄：測試場景與目標

不管單層還多層，都可以多加一欄 `測試場景與目標`，每個最底層分組（SCENE）填一次
簡短描述即可（同一個 SCENE 底下其他列留空也沒關係，程式只取第一筆非空值）。
欄名也接受 `測試場景`、以及舊名 `測試情境與目標`／`測試情境`：

| 層1 | 層2 | 測試場景與目標 | 問題ID | 問題內容 |
|---|---|---|---|---|
| 急救站防護與初期建立 | SCENE A1 | 急救站整體介紹與韌性醫療定位 | 1-1 | 問題內容一 |
| 急救站防護與初期建立 | SCENE A1 |  | 1-2 | 問題內容二 |

這欄沒填也完全沒問題（不會報錯，程式會自動退回用 SCENE 名稱）。填了的話：
`Start.dc.html` 選擇畫面的項目列表文字會優先顯示這段說明而不是單純的編號；
`Analysis.html`「4S 分析」頁的「場景編號對照表」也會用這欄內容對照每個 SCENE
短代號（例如「A1」）代表的完整測試場景；三項潛能雷達圖與「演習覆蓋率」頁底下的
表格裡（兩處共用同一個表格元件），場景編號**點下去會跳出這段說明**
（沒填這一欄的場景不會變成可點的按鈕）。

## 設定試算表填寫說明（對應指標，給分析頁 `Analysis.html` 用）

設定試算表（`CONFIG_SPREADSHEET_ID` 那份）裡的「對應指標」工作表，除了原本寫
入 `評核紀錄`「指標代號」用的三欄，`Analysis.html` 還需要多兩欄才能畫潛能雷
達圖和 4S 長條圖。這張表屬於設定資料（定義每題的潛能/4S/指標對應），不是送
出後才產生的紀錄，所以放在設定試算表，不是紀錄試算表：

> ⚠️ **這一節原本列的欄名，有四個在你的表上其實不存在。** 程式對這張表一律用
> **別名比對**（同一個欄位接受好幾種寫法），而先前這份文件寫的是別名清單裡的
> 第一個寫法，你的表用的是第二個——所以「照文件改表頭」反而會把對得上的改成
> 對不上的。**你的表頭不用動。** 下表第一欄寫的是你現在實際的欄名。

| 你表上的欄名 | 這一欄**還**接受的寫法 | 內容範例 |
|---|---|---|
| `評核題號` | `問題ID` | `1-1` |
| `具體評核題目` | `問題` | 透過預先規劃策略…達到何種層級？ |
| `單一指標對應`（你表上這格裡面有換行，第二行是 `(RAG / 覆蓋率)`） | `問題所屬指標` | 預期6 (預先規劃策略) |
| `評核潛能` | **沒有別名，只能寫這五個字** | `預期` |
| `單一 4S 元素` | `4S 元素`（⚠️ `4S` 與 `元素` 之間要有一個半形空格） | `Space (空間)` |

> ⚠️ **這一欄只能填上表列出的寫法，別的都不行，而且有幾個特別容易填錯：**
>
> - `潛能`（少「評核」兩字）、`4S元素`（少中間那個空格）、`評核題目`（少「具體」兩字）、
>   `指標代號` —— 這四個**都不被接受**。它們是**另一張表**（評核紀錄）的欄名，
>   在這張表上填了會讓 `action=analysis` 整支失敗、分析頁與報告一起打不開。
> - `4S 元素` 與 `4S元素` 只差一個半形空格，肉眼幾乎看不出來，但只有**有空格**那個行得通。
>
> 最保險的做法：**這張表的表頭就別動。** 它現在是對的。

（你的表另外還有 `情境階段`、`演練單元` 兩欄，這張表上不會被讀到，留著無妨。）

- `評核潛能` 欄目前只認得三個會進雷達圖/4S 分析的值：**`反應`**、`監測`、`預期`。
  **舊寫法 `回應` 也完全可以**——程式會自動把它當成 `反應`，你表上現在填的就還是
  `回應`，不用改。填 `學習` 的題目**不會進任何圖表與統計**，但它**仍然算進畫面上
  那張「評核總數」卡**（所以評核總數會大於所有圖表題數相加，那是正常的）；
  欄位裡含有「覆蓋率」字樣（例如 `演習覆蓋率`）的題目會被歸到「覆蓋率」分頁，
  不混進三項潛能統計。
- `4S 元素` 是自由文字，分析頁會依實際出現過的文字動態分組（不是寫死
  `Space (空間)`/`Staff (人員)`/`Stuff (物資)`/`System (系統)` 這四個字串），
  但同一個 4S 類別要用完全一致的文字，否則會被當成不同類別。
- **上表五欄缺一不可。** 任何一欄找不到（欄名寫成上表兩欄都沒列的字、或整欄不見），
  `doGet?action=analysis` 就會直接回錯誤訊息，不會生出半殘的圖表——而且分析頁與
  `Report.gs` 的報告會一起打不開。出錯時**五欄都要檢查**，不是只檢查潛能與 4S。

## 紀錄試算表填寫說明（評核紀錄）

「演習評核_紀錄」試算表的「評核紀錄」工作表是**程式寫入**的那一張，平常不用手
動填，但「表格上有哪幾欄」是你決定的 —— 程式一律比對標頭列的**文字**（不是欄
位位置），所以欄位順序隨便排，想要哪一欄就加哪一欄。

必要欄缺一不可，缺了送出會直接失敗：

| 欄名（可用的別名） | 寫入內容 |
|---|---|
| `問題ID`（`評核題號`） | 該題題號，例如 `1-1`。寫入前會強制把儲存格設成純文字格式，所以不會被 Google 試算表自動變成日期 |
| `分數` | 1–5 |
| `人員代號` | 送出者在「人員代號」工作表裡的代號 |
| `送出時間` | 伺服器當下時間 |

其餘全部是**選填欄：加了就寫、沒加就跳過，不會報錯**。這也是為什麼形狀完全不同的
表格不用改程式就都能用——例如早期那張有 `演習名稱`/`項目名稱`/`指標代號` 的表，
跟現在這張 7 欄的表。2026-10-12 實測，你表上的表頭逐字是
`情境階段`／`演練單元`／`評核題號`／`分數`／`人員代號`／`送出時間`／`觀察紀錄`
（範圍 `A1:G123`）——第一欄是**舊名**，那完全沒問題，兩個寫法程式都認得。

| 欄名（可用的別名） | 寫入內容 | 加了之後有什麼差別 |
|---|---|---|
| `演習名稱` | 設定表「演習資訊」的演習名稱 | 純備查 |
| `項目名稱` | 送出時選的那個最底層項目名稱 | 純備查 |
| `場景階段`（舊名 `情境階段` 仍可用，你表上現在就是舊名） | 該題在「項目與問題」裡的最上層分組名稱 | 分析頁的「階段」欄 |
| `演練單元` | 該題所屬的最底層項目（SCENE）名稱 | 分析頁的「項目」欄 |
| `指標代號` | 從「對應指標」查到的指標 | **新：分析頁現在也會讀回這一欄**，有填就優先用它（見下方「標籤快照」）。⚠️ 但這**不代表**可以不維護「對應指標」——分析每次都還是會整張讀它，刪掉或改壞它，分析頁一樣打不開 |

### 新增的選填欄（加了才有，不加完全照舊）

下面前七欄是後來才加的（最後一列 `指標代號` 本來就有，列在這裡是因為它也屬於下方的「標籤快照」）。**這七欄裡現在只加了 `觀察紀錄` 一欄**（2026-10-12 實測），
其餘六欄還沒加，所以那六欄的效果目前都還沒發生。要用就在「評核紀錄」的標頭列
補上欄名即可，不用重新部署。

| 欄名（可用的別名） | 寫入內容 | 為什麼值得加 |
|---|---|---|
| `觀察紀錄`（`觀察意見`／`質性觀察`／`備註`） | 評核官在該題文字框裡寫的字，送出前自動去頭尾空白並截到 500 字 | **最重要的一欄。** 沒有它，報告永遠只有「反應 3.4」而沒有「為什麼」。加上它之後，列印報告會多一整章「觀察紀錄彙整」 |
| `醫院代號`（`機構代號`） | 連結裡 `?t=` 解析出的機構代號；沒用註冊表時是空字串 | 日後要把多場資料合在一起看時，才知道哪一列屬於誰 |
| `演習代號`（`場次代號`） | 連結裡 `?ex=` 解析出的場次代號；沒用註冊表時是空字串 | 同上。這一欄同樣會被強制設成純文字格式，所以填 `2026-01` 也不會被變成日期 |

> **標籤快照**：不加這五欄時，報告上的「測試場景／評核潛能／4S 元素／題目／指
> 標」是**看報告的那一刻**才回頭去設定試算表對照出來的 —— 所以你為了下一場演習
> 改了題庫，上一場已經印出來的報告再打開一次，標籤就跟紙本對不上，而且沒有任何
> 警告。加了這五欄之後，**送出的瞬間就把標籤寫死在那一列**，之後怎麼改設定表都
> 不會回頭動到它。分析頁的「資料品質」章節會明白印出「本報告標籤取自送出當時快
> 照 N 題／讀取時對照 M 題」，所以兩種狀態都看得出來，不會混淆。
>
> 混合也沒問題：有填的格用快照、空白的格自動退回去對照設定表。舊的列不用補。

### 關於「觀察紀錄」文字框

- 問卷上每一題的評分按鈕下方會有一個文字框，**預設是選填**，提示文字「觀察紀錄
  （選填）」。
- 設定表「演習資訊」加一列 `啟用觀察紀錄` = `N` 可以整個關掉它。
- 設定表「演習資訊」加一列 `低分需說明門檻` = `2`，評 1 或 2 分的題目就會變成
  **必填**：提示文字換成「觀察紀錄（評 2 分以下必填）」，沒寫的話該題下方出現紅
  字提醒，而且整張問卷的送出按鈕會鎖住。
- 這個「必填」只擋在手機端。**伺服器永遠不會因為沒寫說明、或文字太長，就拒收整
  筆分數** —— 分數比留言重要，不能讓一個留言規則吃掉評核官已經填完的一整頁。
- 「評核紀錄」上沒有 `觀察紀錄` 欄時，文字框還是會出現、也送得出去，只是那段文
  字沒有地方可以落地（寫入時整欄跳過）。要留下來就先把欄位加上。
